## Task
Level 20 capstone: `ae.resp`, a Redis-style system: RESP2 codec, command engine (strings, lists, TTL, MULTI/EXEC), append-only-file replay/rewrite, loopback TCP server.

## What worked
- Design first: the key decision was that the log holds *deterministic* commands. Relative TTLs become `PXAT`, lazy expiry is logged as `DEL`, and replay runs with frozen time, followed by a logged purge at open.
- A `RespException.truncated()` flag separates a torn tail (repair by truncating the file) from mid-file garbage (fail). An exhaustive cut-at-every-byte test covers it.
- A differential test against a naive map model with random ops, expiry, and reopen-from-log every few ops. Dropping the lazy-expiry `DEL` log line made it fail, so it has teeth.
- All 44 tests passed on the first full run.

## What failed
- My `sed` that set the pom `artifactId` replaced every `<artifactId>` (dependency and plugins too), so the first `mvn` run failed on dependency resolution. Cost one attempt; not a code bug.
- Drafts of a few tests contained ternary placeholder expressions and an inconsistent expectation (APPEND returning chars vs STRLEN bytes); caught by rereading before the first run.

## Root cause
- Unscoped `sed` on a file with repeated tags. The template has a single `CHANGE_ME`, so substitute only that.
- Mixing character and byte lengths in a spec without stating which one a command returns.

## Rule learned
- Copy the template pom with `sed 's/CHANGE_ME/<run-id>/'`, never a generic `<artifactId>` pattern, and diff against the template afterwards.
- For logs/WALs that replay: log the effect, not the request. Anything time-dependent (TTL, lazy expiry) must be made absolute or logged as an explicit event, and replay must not consult the real clock.
- State once whether string lengths are chars or UTF-8 bytes, and test with a non-ASCII value.
