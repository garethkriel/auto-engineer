## Task
Level 15 networking practice: `ae.net.ResilientHttp`, an `HttpClient` wrapper with idempotency-aware retries, Retry-After, exponential backoff and a delay budget, tested against an in-process `HttpServer`. Overlap check: benchmark has ratelimit/miniserver/cache names; this is a client-side retry wrapper, no server or limiter algorithm.

## What worked
Injecting a `Sleeper` and keeping backoff a pure function let tests assert exact delay lists without sleeping. An `HttpServer` on port 0 with a scripted reply queue (status, body, Retry-After, server delay) made every scenario deterministic; the full class passed 5 consecutive runs (19 tests).

## What failed
First run: `connectionRefusedExhaustsAndThrowsLastWithSuppressed` expected 2 suppressed exceptions, got 1.

## Root cause
Each new failure did `e.addSuppressed(previous)`, which chains failures nested (e3 holds e2, e2 holds e1) instead of attaching all earlier ones to the final exception; the code did not match the spec sentence "earlier ones added as suppressed".

## Rule learned
When reporting several attempts' failures, collect them in a list and attach all earlier ones to the exception that is thrown; test `getSuppressed().length` for 3+ attempts so nesting cannot hide.
