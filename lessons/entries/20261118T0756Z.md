## Task
Level 16 (advanced data structures): `RollbackDsu` (union by size, no path compression, snapshot/rollback) and `OfflineConnectivity` (edge add/remove/query timeline answered by divide and conquer over time). Overlap check: benchmark has j08-graph, j15-topo, j23-segtree; this is neither graph search nor range queries, so no core algorithm overlaps.

## What worked
Writing the BFS oracle and a random timeline generator first (generator tracks live edges so every Remove is valid) gave 300 differential rounds plus hand-written literal cases (path break, duplicate multi-edges, re-add, self-loop). `mvn -q -B clean test` passed on attempt 1: 17 tests, 0 failures. A history stack that stores only the attached child root is enough to undo a merge.

## What failed
Nothing failed at runtime. One test I drafted used a ternary inside an assertion (`componentSize(0 == d.find(1) ? 0 : 1)`) that obscured intent; I caught it on re-read and replaced it with explicit assertions on sizes and connectivity.

## Root cause
Convoluted expected-value expressions creep in when the post-state is awkward to describe; they would hide a wrong expectation. The undo-structure risk (not restoring size/components) is covered only by asserting every observable (connected, componentSize, components, snapshot) after rollback.

## Rule learned
For undoable structures, assert all observable state (connectivity, sizes, counts, snapshot marker) after a rollback, and test a no-op operation is not recorded; for offline/timeline algorithms, pair literal cases with a naive rebuild-and-recompute oracle fed by a generator that keeps its own live-set so inputs are always valid.
