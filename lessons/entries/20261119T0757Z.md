# Lesson 20261119T0757Z

## Task
Level 20 capstone: `ae.broker`, an in-process Kafka-style broker (partitioned logs with retention, keyed and round-robin produce, consumer groups with generations, round-robin rebalance, session expiry on an injected clock, generation-fenced poll/commit, at-least-once redelivery from committed offsets, lag). Overlap check against `benchmark/java/`: j24-queue is a blocking queue, j29-kvlog a crash-safe key-value file; neither has partitions, groups, generations or committed offsets. Chosen after rejected PR #92 (mini-SQL overlapped j35).

## What worked
Writing the contract in TASK.md first (who bumps the generation, when positions reset, what commit may accept) so each test had one unambiguous literal. 20 unit tests with hand-derived expected values plus a 40-seed random simulation. Adding a read-only `assignments(group)` view so the single-owner invariant check does not refresh sessions: my first draft heartbeated every live member after every step, which would have kept everyone alive and silently disabled expiry in the simulation. Four mutants (no position reset on rebalance, no generation check in commit, eviction disabled, `>=` instead of `>` on expiry) were each killed by a named unit test.

## What failed
Nothing failed at runtime: 21 of 21 passed on attempt 1. Defects caught before running: a placeholder ternary assertion (`assertEquals(1, x > 0 ? 1 : 1)`) in the drain step, which can never fail, and the session-refreshing invariant probe above. The random simulation alone does not kill the "no position reset" mutant; only the unit tests do.

## Root cause
Both pre-run defects came from writing an invariant check that used the public API under test, whose side effects (heartbeat refreshes lastSeen) change the behaviour being simulated. The placeholder assertion came from rushing the final drain step.

## Rule learned
In simulations, observe state through a side-effect-free accessor, never through an API that refreshes time-based state, and prove the simulation can fail by mutating each safety rule once. Re-read drafts for ternaries inside assertions before the first run. For consumer-group designs: fence every poll and commit by generation, reset positions to committed offsets on rebalance, and test one redelivery case with hand-listed `partition:offset` literals.
