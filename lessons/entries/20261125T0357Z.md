## Task
Level 20 capstone: `ae.net`, an IPv4 toolkit (Internet checksum with incremental update, strict header codec, MTU fragmenter, stateful reassembler with timeout/eviction, UDP pseudo-header checksum). Overlap check against the 35 `benchmark/java` directory names (listed in TASK.md): none is a packet task; j05-intervals/j16-ranges merge intervals but the core here is protocol buffering and codec validation, not interval merging.

## What worked
80 tests, passed on attempt 2. Published literals (Wikipedia header checksum 0xb861, RFC 1071 example 0x220d) plus a UDP literal computed by an independent Python sum pinned the checksum code. A per-step byte-coverage oracle (first writer wins, complete when last seen and all bytes covered) compared against the reassembler after every random fragment. A 24-mutant pass killed 22 outright, one was equivalent (redundant `head != null`, removed), one was a real gap.

## What failed
First run: 2 test defects. (1) I built a "last fragment" at offset 0 with MF clear; by spec that is a non-fragment and passes through, so my malformed-last test and the random oracle were wrong. (2) My first RFC 1624 corner test assumed `update` equals a recompute even for the 0x0000/0xffff pair. Also my reseal helper read past a 22-byte array, caught before running. The mutation pass found that a second last fragment ending later than the first was accepted silently (the existing conflict test only used a shorter one).

## Root cause
I wrote tests from the data-structure view (a fragment is a range) without first writing the protocol classification rule (offset 0 and MF clear means not a fragment), and I tested only one direction of a two-sided comparison (end < lastEnd but not end > lastEnd).

## Rule learned
For classification rules and equality checks, write the rule table before the tests and generate test inputs from the post-classification domain (here: last fragments at offset >= 1). Test both sides of every comparison (shorter and longer), treat ones-complement zero as two representations when comparing incremental and full checksums, and keep a mutation pass that flips each comparison operator once.
