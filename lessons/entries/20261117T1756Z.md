## Task
Level 13 (language tools): `tpl` mini template engine with variables/dotted paths, filters, if/elif/else with and/or/not, for with `loop.*`, comments, whitespace control, HTML escaping and 1-based line/column syntax and render errors. Overlap check: benchmark dirs j07-expr, j14-json, j20-cron, j22-regex, j28-script, j35-minisql are expression/JSON/cron/regex/script/SQL tasks; a text-to-text template engine with block tags is none of them.

## What worked
- Writing the error-position tests first (exact line/column per error kind) forced one `Source` offset→line/column helper used by both parser and renderer.
- Two stages (raw split, then recursive descent over a sealed-interface AST) kept whitespace control and comments out of the grammar.
- A seeded fuzz test (20000 random fragment strings, only `TemplateException` may escape) plus a time-bounded 100k-loop render.

## What failed
Attempt 1: 54/55 tests passed; `unclosedBlockReportsOpeningTagPosition` failed because `{% for %}{% if %}..{% endif %}` with no `endfor` parsed without error. I also mis-counted one expected column (11 vs 12) when writing the test and fixed it by counting characters before running code.

## Root cause
`nodes()` signalled "stopped by a closing tag" through the mutable field `stop`; a nested block's stop tag stayed in the field when the outer loop ran out of input, so the caller believed its own block had been closed. State used as an out-parameter was not reset on the exhausted-input path.

## Rule learned
When a recursive parser reports "which terminator ended me" through a field, reset it on every exit path (including end of input) or return it as part of a result value; always add a test where an inner block closes properly and the outer one does not.
