## Task
Level 15 networking practice: `ae.net.TcpRelay`, a raw-socket TCP forwarding proxy (half-close, shared idle timeout, connection cap, stats, clean shutdown) tested against in-process echo and scripted upstream servers. Overlap check: benchmark names (miniserver, ratelimit, kvlog...) are servers/algorithms; a byte-level proxy matches none.

## What worked
Writing the hard-to-get-right behaviours as tests first (half-close reply, one-way streaming not counted as idle, limit slot reuse, close() with live connections) shaped the design: a shared `lastActivity` timestamp checked on `SO_TIMEOUT` polls, reservation of the connection slot in the single accept thread, and idempotent `finish()`. All 12 tests passed on the first run and on 6 repeat runs; no debugging needed.

## What failed
Nothing failed this round (attempts = 1).

## Root cause
No defect surfaced. The risks I designed against: per-direction timeouts would close a healthy connection that streams one way only; forwarding EOF with `close()` instead of `shutdownOutput()` would lose the reply in a half-closed exchange; counting "active" from the worker thread would let a burst overshoot the cap.

## Rule learned
For proxies/relays, treat idleness as connection-wide (shared timestamp), forward EOF as `shutdownOutput` not `close`, reserve capacity in the single accept thread, and give each of these a dedicated test (one-way streaming, upstream reads-until-EOF-then-replies, limit-then-reuse) so the failure mode is observable.
