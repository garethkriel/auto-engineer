## Task
Level-20 capstone: disk-backed B+tree (`ae.btree`) with a pinning LRU buffer pool, free list, invariant checker, persistence. Chosen to avoid the benchmark topics (ratelimit, miniserver, minisql); PR #92 was rejected for overlapping `j35-minisql`.

## What worked
Layering (PageFile, BufferPool, tree) with a documented page layout in TASK.md; a `check()` that also verifies the leaf chain, depths, bounds and page accounting (meta + tree + free == pageCount) ran after every mutation of a TreeMap differential test. Mutating the single "relink next.prev on leaf delete" rule was caught by three tests.

## What failed
Attempt 1: `tinyPoolGivesSameAnswersAndEvicts` threw "all 6 frames are pinned" in a height-5 tree.

## Root cause
Recursive insert holds one pin per level plus the new sibling page plus the old next leaf, so it needs height+2 frames; my fixture chose pool size without computing the height of a 64-byte-page tree with 400 keys. The code was right; the fixture violated the documented precondition.

## Rule learned
For pinned-frame designs, state the minimum pool as a function of height in TASK.md and size test pools from the worst-case height of the test data (cap-3 nodes get tall fast); keep the pin count at zero between operations and assert it in the checker.
