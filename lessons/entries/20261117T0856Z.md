## Task
Level 10 (concurrency): `singleflight.SingleFlight<K,V>`, coalescing concurrent calls per key into one execution on a supplied `Executor`, returning `CompletableFuture`s. Overlap check vs `benchmark/java/` names: none is call coalescing; it keeps no results, so it is not the cache tasks (j03-lru, j17-cache).

## What worked
Removing the key from the in-flight map before completing the shared future made "continuation re-calls run" correct by construction. Returning `shared.copy()` per caller isolated cancellation. Tests latched the task open so coalescing was asserted deterministically (`inFlight()==1` with 20 callers).

## What failed
Attempt 1: the stress test timed out in `CyclicBarrier.await` (11 of 12 tests passed).

## Root cause
Test defect: a 64-party barrier was used on a 16-thread pool, so only 16 callers could ever arrive and the barrier could never trip. Production code was not at fault.

## Rule learned
Any barrier/latch that N tasks must reach together needs a pool with at least N threads; size the pool from the same variable as the party count.
