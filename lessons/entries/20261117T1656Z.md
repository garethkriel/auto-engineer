## Task
`tmpl.Template`: a text template engine (level 13, language tools) with `{{ expr | filter }}`, `{% if/elif/else %}`, `{% for %}` with `loop.*`, comments, whitespace control, HTML escaping and exact line/column errors. Overlap check against `benchmark/java/` directory names (j07-expr, j14-json, j22-regex, j28-script, j35-minisql, j04-csv, j20-cron): none is a mixed text/markup template engine; the expression language is only a condition/filter language.

## What worked
Writing the error-position tests first forced a single design decision up front: every token carries an absolute source offset and one `Positions` helper converts it to line/column, so syntax and render errors share code. I derived all column expectations by hand from the literal strings before writing code, and wrote down the rule "EOF errors point at the end of the last token; unclosed blocks point at the opening tag; stray tags point at themselves". 67 tests passed on attempt 1. I then ran two mutations (`&&` to `&`, column off by one) and confirmed the suite failed (15 failures), proving the tests can fail.

## What failed
Nothing failed at run time. While drafting I wrote three tests with `.replace(...)`/`.isEmpty() ? ... :` hacks that could never fail; I caught them on re-reading and rewrote them as plain assertions. Several hand-computed columns in my first draft were off by one or two (e.g. 1-based column of the token after `{% else `); I recomputed each from character counts before running.

## Root cause
Writing expected values while thinking about the code leads to approximations; and convoluted string-munging in a test hides that it asserts nothing. Both are the same failure: the expectation is not independent of the implementation.

## Rule learned
For parsers and tokenisers: carry absolute offsets on every token, convert to line/column in one helper, and write the position table (token, offset, 1-based column) from character counts before coding. Always add a recursion depth limit that raises the language's own error, a seeded garbage fuzz asserting only the library's exception type escapes, and one or two deliberate mutations (short-circuit, column off-by-one) to prove the tests bite.
