# 20261126T0356Z — public-key toolkit (ae.pk)

## Task
P-256/secp256k1 arithmetic, RFC 6979 ECDSA, strict DER, ECDH, Miller-Rabin and RSA PKCS#1 v1.5, verified against RFC vectors and the JDK. Overlap check: read `benchmark/java/` names (j01-roman … j35-minisql); none is public-key crypto.

## What worked
- Differential oracles that are exact, not statistical: RSA PKCS#1 v1.5 is deterministic so our signature bytes must equal the JDK's; RFC 6979 makes ECDSA deterministic so published (k, r, s) literals are checked; the naive affine double-and-add in the test file checks the Jacobian code.
- A tiny curve found by brute force in the test (p=103, prime order > 60) makes rare paths reachable: nonce retry, every scalar, every key, and byte-wide coordinates where `x + p` still fits in a byte, so canonical-coordinate checks can be tested at the exact boundary.
- Mutation pass (45 mutants) found 8 test gaps among 12 survivors; all closed, 4 justified as equivalent.

## What failed
- Attempt 1 passed all 38 tests, yet 12 mutants survived: hash >= n reduction, `x == p` alias, long-form DER length 128, stripped-leading-zero RSA signature, missing qinv validation, odd key size, and a separation guard that random keys never trip.
- Two of my own toy-curve assertions were wrong (not code defects): I asserted the naive accumulator ends at infinity after n+1 additions, and that a wrong key never verifies although about 1/n of wrong keys do on a ~100-element group.

## Root cause
Passing tests on the real 256-bit curves cannot reach conditions with probability 2^-32 or less (hash >= n, nearby primes, `x == p`), and each validation rule needs its own fixture that violates only that rule. Hand-written expectations on tiny groups must account for collisions and off-by-one in loop counts.

## Rule learned
For crypto/number-theory code, write one fixture per validation rule that violates only that rule (stripped leading zero, hash = n+1, x = p, qinv+1, odd bit length), and extract improbable-by-randomness guards into package-private predicates so a boundary test can call them. Use a brute-forced toy parameter set for rare-path coverage, and phrase expectations on tiny groups as rates, not "never".
Survivors justified as equivalent: `jDouble` y==0 test (no order-2 point in a prime-order group); `r >= n` in verify (masked by `x mod n == r`); DER `i+2+len > length` (masked by the final position check); trial division in Miller-Rabin (masked by the bases).
