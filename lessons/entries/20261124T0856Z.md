## Task
Level 20 capstone `ae.rangecoder`: LZMA-style range coder (frequency + adaptive-bit coding), Fenwick adaptive model, byte compressor with 5 engines and a CRC container. Overlap check: benchmark j01-j35 contains no entropy/arithmetic coder; skill `deflate-codec` is LZ+Huffman, different algorithm.

## What worked
- Tests first; the coder, carry handling (`cache`/`cacheSize`) and decoder-relative `code` were correct on the first compile: all round trips passed immediately.
- Measuring the outcome mix: a `carries()` diagnostic plus an assertion `> 0` exposed that my first "carry" fixture (freq 65535 near the bottom) never produced a carry.
- Entropy bounds computed independently in the test (empirical entropy from byte counts) caught real model properties instead of mirroring code.
- Hand mutation (13 mutants) found three real test gaps: ratio guard on claimed length, leading-zero check, and the order-2 context cap (closed with a package-private `order2ContextCount` hook).

## What failed
- First `mvn test`: 5 failures, all in tests: (1) Fenwick boundary: I wrote the last unit of symbol 1 as `INCREMENT` but it is `INCREMENT + 1` (freq 1 + 32, cum 1); (2) 1 MB of zeros expected < 3000 bytes, but the 11-bit/shift-5 `BitModel` saturates at p = 1 - 31/2048 so it costs ~22 KB; (3) BIT0 on an iid source was 9% over entropy (9557 vs 8755), not 3%; (4) order-1 engines differed by 22%, not 10%; (5) the carry fixture produced no carries. Fixed in tests only (attempt 2 green).

## Root cause
Expectations were written from the ideal model (an ideal arithmetic coder reaches entropy and ~0 cost on constant input) instead of from the actual model's parameters: fast-decay probability counters have a floor on cost per bit and an adaptation tax, and Fenwick/interval boundaries need the frequency from the fixture, not the increment alone.

## Rule learned
- Before asserting a compression-size bound, derive the bound from the model's parameters (probability floor = 1 - 31/2048 for an 11-bit shift-5 model; decay window ~32 observations) and record the measured value in a comment; keep a tight bound (3%) only for the count-based model.
- Boundary expectations on cumulative-frequency models: write `cum`/`freq` of the symbol from the fixture (freq = 1 + INCREMENT), then the last/first unit of each interval.
- A "this path happens" diagnostic counter (carries, rescales) plus `assertTrue(count > 0)` is the cheapest guard against fixtures that never reach the rare path; design the fixture to hit the carry (wide intervals in the upper half), not the extreme-frequency one.
- Resource guards (context-count cap, length/ratio bound) are invisible to round-trip tests: add a tiny package-private hook or a crafted input and run a mutation that removes the guard.
