# 20261118T1656Z: consistent-hash ring with vnodes, replicas, bounded load (level 19)

## Task
`ae.ring`: immutable weighted consistent-hash ring, replica preference lists, arc-share computation, bounded-load assignment and rebalance diffs. Overlap check: `benchmark/java/` has j34-vclock, j13-ratelimit, j17-cache, none about hashing/placement, so no overlap.

## What worked
A table `Hasher` gave exact-position tests (wraparound, point equal to key, collisions) before any statistical test; real-hash tests then checked minimal movement (adding a node moves keys only to it; removing moves only its keys), balance, weight proportionality and bounded-load caps. Unsigned ordering by XOR with `Long.MIN_VALUE` worked first time.

## What failed
Attempt 1: two tests failed. (1) `singleNodeOwnsEverything` asserted share `== 1.0` exactly but 128 summed double arcs gave 0.9999999999999997. (2) The collision test expected a node that lost its only point to still appear in `preferenceList`, contradicting my own design comment.

## Root cause
Both were test defects: exact equality on a floating-point sum, and a hand-written expectation that ignored a consequence of my own collision rule (a node with zero points is unreachable).

## Rule learned
Compare summed fractions with a tolerance (1e-12), and when a tie-break rule can eliminate an entity entirely, state in the test what happens to that entity (member but unreachable) before writing the expectation. For placement algorithms, pair exact table-hasher tests with property tests for minimal movement.
