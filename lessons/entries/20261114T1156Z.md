## Root cause
Not applicable to failures. The design risks were (a) using `value == null` as "not computed", which would break null results, and (b) writing the flag before the value, which breaks double-checked locking; both were avoided by writing value first, then the volatile flag, under the lock.

## Rule learned
For memoising wrappers, keep a separate volatile "done" flag written after the value (never use null as the sentinel), assign it only after the supplier returns so exceptions are retried, and test null results, failure-then-success and concurrent first access explicitly.
