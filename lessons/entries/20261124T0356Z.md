## Task
Level 20 capstone: `ae.bigint.Big`, arbitrary-precision signed integers from scratch (Karatsuba, Knuth D division, modPow/modInverse/gcd/isqrt, floor shifts, radix 2..36 I/O), with `java.math.BigInteger` as test-only oracle. Overlap check: `benchmark/java/` j01-j35 has no big-number task (nearest: none; j27-primes is a sieve); `skills/java/` has only long-based `fraction` and `prime-sieve-number-theory`.

## What worked
- Oracle-per-operation differential tests plus operands built from extreme limbs (0, 1, 0x7fffffff, 0x80000000, 0xffffffff); a package-private add-back counter asserted > 0 proves the rare Knuth D6 branch actually ran.
- Package-private `mulSchool`/`mulKaratsuba(threshold)` let tests force deep Karatsuba recursion with threshold 2 on small operands instead of needing huge numbers.
- Mutation run (15 mutants): 12 killed at once; the 3 survivors were analysed instead of ignored.

## What failed
- Attempt 1: `parseAndFormatRoundTripAgainstOracle` threw `ArrayIndexOutOfBoundsException: Index 9 out of bounds for length 9` in `mulAddSmall` during `Big.parse(s, 36)`.
- Mutants `modpow-e0` (`ONE` instead of `ONE.mod(m)`) survived: no test used modulus 1 with exponent 0. Fixed with a literal test, then killed.

## Root cause
The parse buffer was sized `length / 8 + 2` limbs, i.e. an assumed 4 bits per digit; radix 36 carries about 5.17 bits per digit, so long base-36 strings overflowed it. The size bound was written for decimal in my head, not derived from the maximum radix.
The `addback` and `qhat-corr` survivors are equivalent mutants: nothing reads the top word after add-back, and when `qhat` overshoots to 2^32 the add-back step still repairs it.

## Rule learned
- Size buffers from the worst-case parameter (max radix: bits per digit = ceil(log2 36) = 6), not the common case, and include the maximum radix in the first randomized round-trip test.
- For a survivor mutant, decide "equivalent or test gap" by reasoning about what reads the changed value; add a literal for each genuine gap (here the degenerate modulus 1 with exponent 0) and document equivalent ones in the skill README.
- Multi-limb arithmetic: build operands from the all-zeros/all-ones/sign-bit limb alphabet, add an exhaustive small-alphabet grid for division, and count rare-branch executions with a package-private counter so the test fails if the branch becomes unreachable.
