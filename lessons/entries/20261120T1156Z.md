## Task
Level 20 capstone: `ae.minisql`, an in-memory SQL engine (lexer, parser with line/col errors, binder, three-valued-logic evaluator, INNER/LEFT joins, GROUP BY/HAVING/aggregates, DML with atomic statements, snapshot transactions) with two interchangeable executors: nested-loop (`NAIVE`) and hash-join + predicate pushdown (`OPTIMIZED`). Overlap check: no SQL-engine task in `benchmark/java/` or `skills/java/` (only the string builder `sql-select-builder`).

## What worked
- Writing TASK.md with explicit semantic decisions first (NULL ordering, static errors before rows, unspecified order of row-level errors) meant tests and code agreed on the first run: 55 tests, 1 attempt.
- A naive executor as an oracle for the optimized one, fed by 1800 seeded random queries with ORDER BY over every output column, plus two independent plain-collection oracles (join+group, left join).
- Binding columns to fully qualified `Col(alias, name)` records gave structural equality for GROUP BY matching and let join-key analysis work from alias sets.
- Mutation kill-checks (16 mutants): all killed except two equivalent ones (representative row of a group; insert uniqueness check order).

## What failed
- Nothing in the engine failed a test. Process slips while drafting: several test lines were written with awkward `.replace(...)` string tricks and two hand-computed expectations were wrong (`id % 2` group counts swapped); I caught both by rereading before the first run.
- A mutant that removed the backtracking increment in LIKE looped forever and hung my mutation runner; a mutant targeting a string in the wrong file was "NOT FOUND". Single-guard mutants of redundant guards (null keys skipped at both build and probe) survive until both are mutated together.

## Root cause
Hand-computed expected rows and test-builder shortcuts are the error-prone part; mutation harnesses need per-mutant timeouts and must report unmatched patterns.

## Rule learned
- For query engines, bind and statically validate before reading rows, and test optimized planners against a naive twin on seeded random queries while asserting the outcome mix (non-empty, hash joins, left joins, pushdown counts).
- Mutation runners need `timeout` per mutant (an infinite-loop mutant counts as killed) and must fail loudly on unmatched patterns; mutate redundant guards together.
- Write test SQL as plain literals; never build expectations with `.replace` on the SQL string.
