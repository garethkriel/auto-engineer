# 20261126T0756Z — binary-to-text codecs (ae.b2t)

## Task
Strict RFC 4648 Base64/Base32, Bitcoin Base58/Base58Check, BIP173/BIP350 Bech32/Bech32m and Segwit addresses. Overlap check: read `benchmark/java/` names j01-roman … j35-minisql; none is a binary-to-text codec.

## What worked
- Bech32 checksums are self-verifying oracles: when a remembered vector failed to decode I could tell the vector (not the code) was wrong because other published vectors and the encode/decode round trip passed.
- Exhaustive single-character substitution over every charset symbol (Bech32 and Base58Check) shows that checksums catch all one-symbol errors.
- Fixture "all ones count in the spare bits" test for Base64 tails: exactly 4 of 64 (1 byte tail) and 16 of 64 (2 byte tail) second/third characters are canonical.
- 13 manual mutants: 9 killed, 4 survived. Survivors: `convertBits` `bits >= from` (a real gap; fixed by a zero-leftover fixture `{0,0,0}` 5->8), `c > 126` in the first Bech32 scan (equivalent, masked by `checkHrp`), padding count check (equivalent, masked by the length-multiple check), `raw.length < 5` (equivalent, `copyOfRange` throws IAE anyway).

## What failed
- Three runs. Run 1: Base64 valid-remainder table was `{T,T,F,T}` instead of `{T,F,T,T}` (index vs value confusion), and several hand-written expectations were wrong: `convertBits({ff,ff},8,5)` is `31,31,31,16` (16 bits = 3 groups + 1 bit), "MY" is a valid Base32 for "f" (Y=11000 spare bits 00), the "82 q" Bech32 vector lacked its separator `1`, and a "non-zero padding" fixture used 20 bytes (32 groups, no spare bits at all).
- Run 2: three remembered BIP vectors (`?1ezyqs3`, `abcdef1l7aum6echk45nes6c0wdl`) did not verify; replaced with vectors that were checksum-valid and a vector built by construction.

## Root cause
Hand-derived expectations skipped the bit arithmetic: group counts and spare-bit counts were guessed instead of computed (16 bits/5 = 3 r 1; 160 bits/5 = 32 r 0). Remembered literals for long checksummed strings are not reliable.

## Rule learned
For bit-regrouping codecs, write a comment table `bits in / group size = groups r spare` before choosing fixtures (a "padding" fixture needs spare > 0), index validity tables by remainder with the valid set written in a comment, and take long published checksum vectors only if the checksum verifies, otherwise build them by construction.
