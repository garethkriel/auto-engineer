## Task
Level 14 (storage): immutable SSTable `ae.sst` with sparse index, Bloom filter, CRC32 footer, tombstones and k-way merge. Overlap check: `benchmark/java/` j29-kvlog and j12-fileindex are an append log and a file index; no shared core algorithm with a sorted immutable table.

## What worked
Building the whole file image in memory before touching disk made "invalid input leaves no file" trivial. Sealing crafted images with a freshly computed CRC isolated structural validation (offsets, index consistency, lying count) from the checksum. Every-byte-flip and truncation loops plus a randomized merge against a TreeMap model gave strong coverage; 14 tests passed on the first run.

## What failed
Nothing failed in the run. While drafting, my first version of the crafted-offset test used confusing conditional expressions and the wrong footer size (24 instead of 28); I caught both on rereading before running.

## Root cause
Footer size was kept in my head instead of derived from the layout; a miscounted constant would have made the crafted test corrupt the wrong bytes and still "pass" as a CorruptSstException.

## Rule learned
Define layout sizes as named constants (FOOTER_SIZE) and use them in tests, and make crafted-corruption tests assert the specific damaged field by building cases from values read back from the good file. Compare keys in one place by the same byte order the file uses (unsigned UTF-8), with a test where String.compareTo disagrees.
