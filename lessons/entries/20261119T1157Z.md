## Task
Level 20 capstone: `ae.coord`, a ZooKeeper-style coordination kernel (sessions, ephemeral/sequential nodes, one-shot watches, atomic multi, fenced fair lock recipe). Overlap check against benchmark/java (j01..j35): none is a namespace/session/watch/lock service; no overlap.

## What worked
- One staged-copy commit path (immutable nodes, copy the map, swap on success) made `multi` atomic and single ops free of side effects for free; no rollback code.
- Queuing watcher callbacks and running them after leaving the monitor; a test with a blocked watcher while another thread uses the service pins it.
- Seeded differential test against a naive path-keyed model plus `checkInvariants()` after every step; a mutation of the expiry boundary (`>=` to `>`) was killed by 7 tests.

## What failed
Attempt 1: 3 failures. (1) Lock handles stayed GRANTED after their session expired because nothing notified them. (2) Same for a WAITING handle. (3) The randomized test read `lastZxid()` before the service's lazy expiry ran, so an expiry transaction looked like a failed multi consuming a zxid.

## Root cause
(1,2) A client-side object cached state that the server can change behind its back (session expiry) and the design had no notification or re-check path for it. (3) Test sampled a counter before the call that lazily advances it.

## Rule learned
Handles that mirror server-side state (locks, leases) must re-verify against the service when asked for their state (or be notified); test the "expired behind its back" path explicitly. In systems with lazy time-driven side effects, force them (`tick()`) before sampling counters for before/after comparisons.
