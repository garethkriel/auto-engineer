# Lesson 20261119T0556Z

## Task
Level 20 capstone: `ae.deflate`, a DEFLATE/zlib codec from scratch (bit reader/writer, canonical Huffman decoder, inflate for stored/fixed/dynamic blocks with an output cap, hash-chain LZ77 deflate emitting a fixed-Huffman block or stored blocks, Adler-32, zlib wrap/unwrap). Overlap check against `benchmark/java/`: no task there involves compression or bit streams (`j18-diff` and `j29-kvlog` share no algorithm).

## What worked
Using the JDK `Deflater`/`Inflater` as independent oracles in tests only: our inflate decoded JDK output at levels 0-9 times 3 strategies on 10 inputs (300 streams, including dynamic blocks I never wrote an encoder for), and the JDK decoded ours. RFC/zlib byte vectors (`4b 04 00`, `cb 48 cd c9 c9 07 00`, `06 2c 02 15`) pinned the bit order. Exhaustive truncation and flip-every-byte loops asserting "data or InflateException only" found nothing in the decoder, and two mutants (window `<=` to `<`, dropping the distance bound) were killed.

## What failed
Attempt 1: 24 of 45 tests failed. Attempt 2: 2 failures and 2 errors. Attempt 3: all 45 green.

## Root cause
Four distinct causes, none a logic bug in the algorithm: (1) the fixed distance Huffman table was built with 30 codes of length 5, which is an incomplete code (the real table has 32 slots, 30 and 31 invalid), so my own strict completeness check made `Inflate`'s static initialiser throw and every test then reported `NoClassDefFoundError`; (2) test expectations: `consumed` semantics were ambiguous (absolute vs relative to the offset) and 1 MB of zeros cannot fit under 2 KB with fixed-Huffman 258-byte matches (about 13 bits each, 6.3 KB); (3) the window-edge test used random filler, so the whole stream fell back to stored blocks and the 32768-distance match never got a chance; (4) the oracle helper: the JDK raw `Inflater` needs a dummy trailing byte and `finished()` must be checked before `needsInput()`.

## Rule learned
When a static initialiser builds validated tables, a defect in it surfaces as `NoClassDefFoundError` in every test: run one test of the class first and read the first stack trace, not the summary. For codecs, write the size/threshold expectations from arithmetic (bits per symbol times symbol count) and make fixtures take the code path under test (compressible filler, so the stored fallback is not chosen), then check that path with a mutant. Fix an API's offset semantics (absolute vs relative) in TASK.md before writing the tests.
