## Task
Level 20 capstone: `ae.regex`, a regex engine built on automata. Parser with indexed syntax errors, Thompson NFA, subset construction over character-class intervals, Moore minimisation to a canonical DFA, leftmost-longest `find`, equivalence with shortest witness, intersection/complement/union, and `count(n)`. Checked against `java.util.regex` and brute-force oracles.

## What worked
- Alphabet as intervals (class boundaries collected from NFA edges) made subset construction independent of the 65536-char alphabet.
- Canonical form (Moore refinement, merge adjacent identical classes, BFS renumbering) gives a cross-check: DFA `equals` must agree with the independent product-construction `equivalent`.
- Verifying the random pattern generator first (every output compiles in both engines), then asserting both accepted/rejected counts are large, kept the differential tests meaningful.
- Mutation kill-checks (drop the optional-copy epsilon, never merge classes, let dot match `\n`, first-match instead of longest, ignore class width in `count`) each failed several tests.

## What failed
Three test runs were needed. Run 1 had 8 failures in `DfaTest.minimalCompleteDfaShape` and 1 in `findAll`. Run 2 had 1 `findAll` failure. All were wrong expectations I had written by hand, not code bugs:
- I expected equivalence-class counts (e.g. 2 for `a*`) but the canonical form counts maximal intervals: the chars below and above `a` are separate non-adjacent intervals, so 3.
- In "aa baaa" I miscounted the second run (4..7, not 3..6).
- For `b*` on "abba" I forgot the legitimate empty match at index 3 after `bb` (java.util.regex does the same).

## Root cause
Expectations for counts and positions were written from intuition instead of derived step by step, and I conflated "behaviour classes" with "intervals". A tell: I had already left placeholder/`|| true` junk assertions in drafts and removed them before the first run.

## Rule learned
- With interval-partitioned alphabets, expected class counts are interval counts. Write the interval boundaries in a comment next to each table row before the number.
- For `findAll` or empty-match scanning, write the sequence of scan positions (position, match or empty) before the expected literal, and compare to `java.util.regex` behaviour.
- Never put `|| true`, ternaries or arithmetic no-ops into assertions. Re-read drafts for them before the first run, and delete a case instead of loosening it.
- Avoid `>` and other shell metacharacters in unquoted `echo` labels (a stray file named `first` appeared); delete stray files before committing.
