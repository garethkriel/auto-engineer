# Lesson 20261124T2356Z

## Task
Game-tree search (`ae.search`): negamax alpha-beta with a transposition table (EXACT/LOWER/UPPER bounds), move ordering, `analyse`, iterative deepening, over `ConnectK` and `SubtractionNim`, with a `Minimax` oracle. Overlap check: listed all 35 `benchmark/java` ids; none is a game or tree search (nearest j08-graph, j32-fsm).

## What worked
Making terminal scores `+-(WIN - ply)` (a function of the position alone) removed the mate-distance correction a table normally needs. Tests were exact-equality against plain minimax: no table at depths 1-4, table at full depth with sizes 1/7/1024/200003, one table reused across 120 searches, Perft literals (549946 nodes, 255168 games, per-ply 1,9,72,504,...), Nim modulo rules up to n=60. `mvn -q -B clean test`: 56 tests, 0 failures, attempt 2.

## What failed
Attempt 1 failed 5 tests: my fixtures used reading-order cell numbers (cell 2 = top-right) while the code indexed from the bottom row. In the mutation check (14 mutants) two survived: `e.depth() >= depth` replaced by `true`, and a full root window instead of the narrowed one. Several drafts also contained placeholder junk (`* 0 +`, arithmetic noise) that I had to find and delete before running.

## Root cause
The cell-numbering convention was decided in code, not in the test fixtures: no comment or TASK.md line fixed "index 0 = top-left". The two survivors were equivalent on every test that searched to the end of the game, because at full depth the table's stored depth always equals the requested depth, and the root window only changes node counts, not values.

## Rule learned
State the coordinate convention (origin, row order) in the class doc and TASK.md before writing fixtures, and make parse() and move numbering share it. For any table depth check, add a test that deepens through one table (depth 1, 2, 3, 4 on the same instance) and compares each result with the plain oracle; for pruning windows, assert a node-count inequality against the unpruned variant, since values cannot reveal them.
