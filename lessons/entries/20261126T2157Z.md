# 20261126T2157Z practice: patch toolkit (ae.patch)

## Task
Minimal line diff, GNU-identical unified diff writer, strict parser, offset/reject/reverse patcher and diff3-style three-way merge. Overlap check: `benchmark/java/j18-diff` is only a minimal edit script; no skill covered unified format, patching or merging.

## What worked
Probing the real tool before fixing semantics: running `diff3 -m` on a dozen tiny cases showed that touching (adjacent) changes conflict, that the conflict spans the union of both sides' base ranges, and that the base section is always printed, so the cluster rule and the renderer were right on the first full run. Generators with fresh unique lines make the minimal script unique, so GNU `diff -U<n>`, `patch --fuzz=0` and `diff3 -m` were usable as exact oracles (120 + 80 + 250 seeded rounds with measured clean/conflict mix). A 21-mutant pass followed.

## What failed
- I wrote `LineDiff`, `Hunk` and `Patch` before their tests (test-first slip); the tests for the rest were written before `UnifiedDiff`, `Patcher` and `Merge3`.
- First differential run: `diff -u -U2` still printed 3 context lines (GNU keeps the `-u` default), so my expected hunks looked wrong. Then GNU `diff3 -m` printed "both sides deleted the same line" as a base/theirs conflict, which no sane merge should copy; the generator hit it by deleting the same base line on both sides.
- A hand-written expectation had the wrong line number (header at line 7, not 6).
- 4 of 21 mutants survived: dropping suffix trimming (equivalent in output, only the heap differs), the "extra body line" check (masked: the line was re-read as a bad hunk header, which also names line 7), the "hunk may not start before consumed lines" guard and the `pos + len <= size` bound (no fixture whose only match lay in consumed text or whose probe ran one line past the end).

## Root cause
Oracle quirks were assumed away instead of measured, and guards that are backed up by another failure path (error masking) or only matter in rare search positions had no fixture of their own.

## Rule learned
When an installed tool is the oracle, run it on a dozen hand cases first and write down its quirks (option precedence, identical-change handling) in TASK.md; restrict the generator to inputs where the tool is unambiguous and count skipped rounds. For each guard, assert the message that only that guard produces; give offset/search loops a fixture whose only candidate lies in already-consumed text and one whose probe runs past the end; and prove "optimisation" code (prefix/suffix trimming) with an input large enough that the unoptimised version exhausts the heap.
