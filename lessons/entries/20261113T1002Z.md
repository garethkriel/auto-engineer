# Lesson 20261113T1002Z

## Task
Level 2 (equals/hashCode, toString, constructors): immutable `Fraction` value class.

## What worked
Canonicalising in one static factory (private constructor) made `equals`/`hashCode` trivial and correct for unreduced inputs. Tests written first for edge cases: `Long.MIN_VALUE` negation, `0/-7`, near-`Long.MAX_VALUE` compareTo, malformed parse strings. All 14 passed on first compile of the code.

## What failed
`mvn -q -B test` failed repeatedly at dependency/plugin resolution ("Could not find artifact ... in central") even though `curl` to the same URLs returned 200. Plain `-U` retries each got one step further (opentest4j, resources, compiler, surefire plugins) until try 3 of a loop succeeded: 14 tests, 0 failures. No code was changed.

## Root cause
Maven Resolver caches transient download failures as `.lastUpdated` and marks the artifact absent; the proxied network drops some jar downloads intermittently, so each run fails on a different artifact. Not a code bug.

## Rule learned
On "Could not find artifact" while curl works, loop `mvn -q -B -U test` a few times (each run caches more artifacts) instead of hand-copying jars or editing code, and don't count it as a debug attempt. For value classes: normalise inside the only factory so equals/hashCode compare plain fields, and use `Math.*Exact`/`BigInteger` for overflow-prone arithmetic and comparison.
