# 20261118T1156Z: refactor access-control checker (level 18)

## Task
Refactor a messy nested-if access checker (string role/action) into Role/Action/Resource/Decision with polymorphic role policies, keeping exact output. Overlap check: no benchmark task is an access-control checker.

## What worked
Keeping the legacy implementation in the test tree as an oracle, plus an exhaustive grid differential test (30k+ inputs incl. null, padded, mixed-case and out-of-range values) next to a literal characterisation table.

## What failed
First run: the differential test failed on `root|null|...`: legacy rejects a null action (`bad-action`) before validating the role name (`unknown-role`). My 36-row hand table covered unknown-role and bad-action separately but never together, so the refactor reordered the checks.

## Root cause
Validation-order dependencies between two independent error checks were an implicit behaviour; I parsed role and action in the "natural" order instead of the legacy order, and the hand-picked table had no row combining two invalid inputs.

## Rule learned
When refactoring a function with several validation guards, copy the guard order verbatim and always add a differential grid over the cross-product of invalid values (null/empty/unknown for every parameter), because hand tables rarely combine two invalid inputs.
