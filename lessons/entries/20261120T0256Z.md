# Lesson 20261120T0256Z — compressed time-series store (level 20)

## Task
`ae.tsdb`: Gorilla-style codec (delta-of-delta timestamps, XOR doubles), block store with min/max block skipping,
aggregates, retention, CRC-sealed snapshot. Overlap check against `benchmark/java/` names done in TASK.md (no match).

## What worked
- Writing the exact bit layout in TASK.md first made the encoder/decoder symmetric; 33 of 35 tests passed first run.
- Bit-exact assertions through `doubleToRawLongBits`, an all-pairs special-double grid, bucket-boundary deltas,
  truncation at every length and flip-every-bit loops pinned the codec. Two mutations (window-reuse condition, dod
  bucket offset) were both caught (6 and 15 failures).
- A "decoded block counter" test hook made block skipping observable rather than inferred.

## What failed
Two tests of mine used wrong hand-computed fixtures: `retain(1075)` assumed a block with max 1070 straddled the cutoff,
and a query `[1035,1045)` assumed it touched block 0 whose max was 1030.

## Root cause
I reasoned about "which block a range touches" from block start times instead of writing each block's `[min,max]` next to
the fixture; a cutoff or range that clears a block's max does not touch it.

## Rule learned
For range/retention tests over sealed blocks, write a comment table of every block's `[min,max]` first and choose
cutoffs/ranges relative to the max (just below, equal, just above); state the half-open convention beside each literal.
