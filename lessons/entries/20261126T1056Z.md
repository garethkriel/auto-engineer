# Lesson 20261126T1056Z: strict ZIP and TAR archive toolkit

## Task
Level 20 capstone: `ae.arch` with CRC-32, name/tree safety rules, a ZIP writer/reader (stored/deflate, central directory, data descriptors) and a POSIX ustar TAR writer/reader, all strict. Overlap check: `benchmark/java/` names j01-roman..j35-minisql read, none is an archive format.

## What worked
- Writing the exact byte layouts (hand-added 110-byte one-file ZIP, ustar checksum 4206 = octal 10156) into the tests before the code.
- Four independent oracles: JDK `ZipInputStream`/`ZipFile`/`ZipOutputStream` (the last one produces bit-3 data descriptors), Info-ZIP `zip`/`unzip`, GNU `tar`.
- A `patch`/`reseal` helper per format so every crafted defect has a control that differs only by that field; exhaustive truncation (every prefix rejected) and flip-every-bit loops.
- A 69-mutant pass: 67 killed, 2 justified as equivalent (extraction-root re-check unreachable because `Names.validate` forbids `.`/`..`; `next > end` off-by-one is also caught by the final `p != end` check).

## What failed
1. Compile error: an expression (`"\u007f".repeat(0) + ...`) inside `@ValueSource`.
2. Magic comparison used `"ustar\000"` (6 bytes) against 8 bytes: `ArrayIndexOutOfBounds` instead of `ArchiveException` on every tar; the reader must never leak a non-`ArchiveException`.
3. The sandbox locale is POSIX, so `Files.createDirectories("naïve")` throws `InvalidPathException` in file-system tests; tests that touch the file system must use ASCII names.
4. A 65535-entry archive was rejected by my own reader because 0xFFFF is the ZIP64 marker; the writer limit had to be 65534.
5. Mutation pass: the first harness read `file|from|to` with `IFS='|'`, which cannot express mutants containing `||` (5 NOMATCH), and killing the harness mid-run left `Crc32.java` mutated (restored by hand from the backup).
6. The mutation pass also showed redundant production guards (duplicate-name check in `readCentral` masked by `checkTree`, octal terminator clause masked by the trailing-bytes loop, padding-fit clause masked by the `length % 512` rule) and untested boundaries (disk-of-central-directory, one-byte overlap, one-byte overrun into the central directory, deflate stream cut short, empty deflated file, AUTO tie case).

## Root cause
Strict parsers accumulate overlapping guards written "to be safe"; without a per-guard kill-check, a guard whose job is done by another guard stays untested, and the boundary of each guard (off by one byte) is where the real gaps were. Separately, test fixtures and harnesses made environmental assumptions (locale, `|` delimiter, no restore on kill).

## Rule learned
- Every guard in a strict parser gets a mutant (`>` to `>=`, `+1`, removal); if removal survives, either name the other guard that masks it and delete the redundancy, or add the boundary test with exactly one byte of excess.
- Readers over untrusted bytes must funnel every bounds failure into the one documented exception type: run a truncation loop asserting `assertThrows(ArchiveException.class, ...)` (not just any exception) from the first test.
- Mutation harnesses: delimit with TAB, `trap` to restore the original file on EXIT/INT/TERM, and never kill them without checking `git status`/`diff` against the backup.
- File-system tests use ASCII names (the cloud locale is POSIX); format constants with in-band markers (0xFFFF = ZIP64) bound the usable range of the classic format.
