# 20261118T1756Z: state-based CRDTs with convergence simulation (level 19)

## Task
`ae.crdt`: immutable GCounter, PNCounter, LwwRegister, OrSet (add-wins) with `merge`. Overlap check: benchmark has j34-vclock only; this uses per-replica slots and unique tags, so no overlap.

## What worked
Passed on attempt 1 (22 tests). Literal scenario tests (concurrent add vs remove, re-add after remove, stamp ties) plus merge-law tests (commutative, associative, idempotent) and seeded gossip simulations checked against an oracle tracked independently of the implementation (a per-replica "seen tags" set for the OR-set, a running sum for counters). Exhaustive law checks over a small enumerated state space for the register.

## What failed
Nothing failed in the run. Process slip: I wrote the main code before the tests, against the test-first rule; the tests still caught nothing because the design was written from the known CRDT laws.

## Root cause
n/a for failures. The slip came from a design I considered "known"; it still violates the loop.

## Rule learned
For replicated types, make merge a join (idempotent, commutative, associative), make equality structural, break every tie by a total order (even on the value), and test convergence by gossip with an oracle that tracks observed operations separately. Write the tests before the code even for well-known designs.
