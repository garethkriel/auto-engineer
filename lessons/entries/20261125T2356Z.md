# 20261125T2356Z — operational transformation editor core

## Task
`ae.ot`: normalised `TextOp`, compose/transform/invert, log-based `Server`, 3-state `Client`, seeded FIFO-channel `Simulation`. Overlap check: `benchmark/java/` j01..j35 (roman .. minisql) contain no OT/collaborative editing task; j18-diff is a different problem.

## What worked
- Writing the tie rule (first argument's insert wins; server history is always first) in TASK.md before the tests, then using it consistently in Server and Client.
- Property tests against naive oracles (sequential apply for compose, both-orders convergence for transform, invert round trip) plus 90 seeded multi-client runs with a workload-size and interleaving check.
- Five single-rule mutants (tie flip in transform, server argument order, buffer transform, missing revision++ on ack, compose insert-vs-retain) all made `mvn test` exit non-zero.

## What failed
- Two first-run failures, both test defects: I expected `[R1, D2, I"bc", R1]` from `invert` although the normal form puts the insert first, and I wrote a "transform of a composed op equals stepwise transform" property that is not true.

## Root cause
The canonical form (insert before adjacent delete) discards which side of a deleted run an insert was on, so composed and stepwise transforms can place a concurrent insert differently while still converging (TP1). I assumed a stronger algebraic law than the data model supports and typed literals without applying the normalisation rule.

## Rule learned
For OT/CRDT-style normal forms, write expected literals through the normaliser rule, test only the guaranteed law (convergence of both orders) and turn any tempting stronger law into a literal test documenting the limitation; verify a mutant is killed by a test failure, not a compile error, by checking the surefire output once.
