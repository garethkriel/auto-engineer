## Task
Level 13 (language tools): `ae.tconf` TOML-subset parser with `[table]`, `[[array]]`, dotted keys, inline tables, escapes, numbers and positioned syntax/semantic errors. Overlap check: benchmark dirs j04-csv, j07-expr, j14-json, j20-cron, j22-regex, j28-script, j35-minisql are flat-row, expression, JSON, cron, regex, script and SQL tasks; a headered, nested config language is none of them.

## What worked
- Writing every error test as `at(doc, line, col)` first fixed one convention: the position is the start of the offending token (key, header segment, opening quote/bracket), so the parser needed only one `error(pos, msg)` helper that derives line/column from an offset.
- Keeping table state (implicit/explicit/dotted/inline) in a parser-side identity map left the public `Table`/`Arr` read-only and made each semantic rule a one-line check.
- A depth cap (256) with a test using 100000 open brackets turned a would-be `StackOverflowError` into a `TomlException`; the seeded fuzz (20000 inputs) and an independent model-vs-parse round trip (300 random nested models) both passed first time.

## What failed
Attempt 1: 69/70 passed. `duplicateKey` expected column 14 for the second `a` in `t = {a = 1, a = 2}`; the real column is 13. The parser was right; I mis-counted by hand.

## Root cause
Hand-counted column in a test expectation (off by one across `, `), not a code defect. It was caught only because the failure message printed document and position together.

## Rule learned
For position assertions, write the document as a literal and mark the target with a trailing counted comment or compute the expected column from `doc.indexOf(token) + 1` in the test; always include the document in the failure message (the `at` helper does).
