# 20261125T2156Z — RV32IM assembler, codec and emulator (level 20)

## Task
`ae.rv`: validated canonical `Instr`, binary `Codec`, two-pass `Assembler` with pseudo-instructions, and a `Cpu` emulator with traps and M-extension semantics. Overlap check: read `benchmark/java/` names (j01-roman … j35-minisql); none is an instruction-set, assembler or machine emulator task (j28-script is a scripting language).

## What worked
Hand-deriving about 16 literal encodings (checked field by field) before writing the codec; making `Instr` canonical so `decode(encode(x)) == x` and `encode(decode(w)) == w` hold for 200k random words; BigInteger oracles for mulh/mulhsu/mulhu/div/rem; mutation pass on 9 single-line mutants (8 killed).

## What failed
Run 1: compile error (my `catch (IllegalArgumentException)` rethrew a type that was not `AsmException`). Run 2: three test defects: `assertEquals` on two `int[]` (reference compare), and the expectation `7 / -2 == 3` (truncation gives -3). A survivor mutant (`check(fetch, 2)`) was unobserved because an illegal-word trap is also a `Trap`.

## Root cause
Test defects only: array equality needs `assertArrayEquals`, and a signed-division expectation was written from intuition instead of computing `-3.5` truncated toward zero. The survivor came from asserting only the exception type when two different causes throw the same type.

## Rule learned
When two failure causes share an exception type (misaligned fetch vs illegal word), assert on the message; compare `int[]` results with `assertArrayEquals` and grep new tests for `assertEquals(asm(`-style array comparisons before the first run; write truncating-division expectations as decimal-then-truncate comments.
