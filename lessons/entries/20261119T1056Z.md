## Task
Level 20 capstone: incremental build engine `ae.build` (dynamic dependencies, value-hash verification, early cutoff, failure memoisation, cycle paths, CRC-sealed canonical store). Overlap check against benchmark/java: j15-topo is static topo sort only; no overlap.

## What worked
- Writing the verify-in-recorded-order rule down in TASK.md first made the dynamic-dependency tests (flip a flag, an irrelevant input changes, nothing reruns) easy to write as literal expectations.
- Exhaustive truncation and flip-every-byte loops plus crafted re-sealed images caught nothing wrong but pin the store format.
- Seeded differential test (incremental vs from-scratch, nothing runs when nothing changed, each rule at most once).

## What failed
Attempt 1: 2 failures, both test defects. (1) The randomized test asserted "no changed input => nothing runs" at step 0, where the first build legitimately runs everything. (2) A save/overwrite test reused a helper that re-seeds the original input, so the reloaded builder saw the old input instead of the saved one.

## Root cause
(1) An invariant about incremental runs was stated without its precondition (a prior run exists). (2) A shared fixture helper silently set state that the test meant to take from the persisted store.

## Rule learned
For "nothing changed => nothing reruns" invariants, state the precondition (a prior run exists) and guard the assertion with it; when a test reloads persisted state into a fixture built by a helper, make the test override the helper's seeded state explicitly and assert the rerun list is empty. Also: a per-step "affected" oracle is unsound for rules that were unreached for a while (stale records), so use a cumulative changed set.
