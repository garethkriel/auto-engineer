# Lesson 20261114T0956Z

## Task
Level 6 file I/O: `RotatingLog` — size-based log rotation with numbered backups (`a.log.1` newest). Overlap check against `benchmark/java/` (roman, wordfreq, lru, csv, intervals, lcs, expr, graph, bank, counter, streams, fileindex): none shares a core algorithm; this is file rotation/shifting.

## What worked
Listing boundary cases before coding (line that exactly fits, line one byte over, oversized line into an empty file, `maxBackups == 0`, multi-byte UTF-8) turned each into a small test. 18 tests passed on attempt 1; a directory-listing assertion proved no stray temp files.

## What failed
Nothing failed. Risk spotted early: counting `String.length()` instead of UTF-8 bytes would under-count, and rotating an empty file for an oversized first line would create a pointless empty backup.

## Root cause
n/a (no defect). Defects avoided: shifting backups lowest-index first (would overwrite `.2` with `.1` before it moved) — shift from highest to lowest; and rotating when `size == 0`.

## Rule learned
When a file operation renames a numbered sequence, shift from the highest index down and delete the cap-index file first; test the exact-fit boundary and the "item larger than the limit" case separately.
