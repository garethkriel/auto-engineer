## Task
Level 9 (recursion, parsing): path glob matcher (`?`, `*`, `**`, `**/`, classes, escapes) with memoised matching. Overlap check against `benchmark/java/` names (roman, wordfreq, lru, csv, intervals, lcs, expr, graph, bank, counter, streams, fileindex): no glob/wildcard task, so it was allowed.

## What worked
Tokenising once and matching via memoised recursion on (token index, position) kept `*a*a*a*a*a*b` on 5000 chars fast (timeout test). A table of literal cases plus error cases and a randomized cross-check against `java.util.regex` gave broad coverage.

## What failed
Attempt 1: the randomized test failed on `**?aa` vs `aaa` (expected false, got true). The code was right; the test's reference translation `replace("*", ".*").replace("?", ".")` produced `.*?aa`, where `?` became a lazy quantifier.

## Root cause
Differential test built the oracle by chained string replacement, so wildcard metacharacters collided with regex metacharacters (`*` followed by `?`). The oracle itself was buggy.

## Rule learned
When a randomized test uses another engine (regex, etc.) as the oracle, translate the input token by token and wrap each translated unit in its own group, and when it fails first check whether the oracle mistranslated the input, minimising the failing case by hand before touching the code.
