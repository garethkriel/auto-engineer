## What failed
Two `mvn` runs. The first failed on a test fixture error: `select0(p)` with `p = n-1` asked for a zero that does not exist (there are only n-1 zeros). Production code was right.

## Root cause
I wrote the expected value as a formula (`select0(p) == p+1`) without checking its validity range at the last boundary position. The same pattern, an index argument whose legal range depends on a count, is where fixtures go wrong.

## Rule learned
For rank/select-style structures, write the legal range of every query argument next to each formula-based expectation (k < count) and include the last boundary position in the fixture list. Pair "answer is correct" tests with an exact formula for space/cost when the structure's point is compactness: a parameter that is off by one still gives correct answers and only an exact `bitsUsed` assertion sees it. When a mutant survives, decide equivalent vs gap by asking whether the changed value is read by anything with a later correcting step (here the scan continuing over blocks).
