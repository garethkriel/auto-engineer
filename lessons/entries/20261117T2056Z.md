## Task
Level 13: `ae.mdlite` Markdown-subset parser (sealed `Block`/`Inline` AST, pattern-matching HTML renderer, line/column errors, URL allow-list, nesting caps). Overlap check: benchmark j04-csv, j07-expr, j14-json, j18-diff, j20-cron, j22-regex, j28-script, j35-minisql are not markup tasks; prior rounds did a template engine and TOML.

## What worked
- Carrying a `Ln(text, line, col)` record through block parsing (prefix stripping just adds to `col`) made error columns inside quotes and list items correct with no extra bookkeeping; one joined char array with per-char line/col did the same for inlines.
- Precomputing bracket matches (stack) and a next-backtick table, plus a per-(delimiter,end) "search failed from here" cache, made 30000 repetitions of `*a `, `[a `, `` `a `` and `**a ` finish well under the 5s bound.
- Fuzz test (20000 random docs) asserting "only MarkdownException, never `<script`" passed first time.

## What failed
Attempt 1: 38/40. (a) The full-render expectation left `"` unescaped inside a code block, but code text is escaped like all text. (b) `para("****")` expected literal text, but four stars is correctly a thematic break.

## Root cause
Both were wrong hand-written expectations (test defects): I wrote the expected HTML from memory of the spec instead of from the stated escaping rule, and forgot that block rules run before inline parsing.

## Rule learned
When a test input could be claimed by several grammar levels, list which block rule fires first (rule/heading/list) before writing the inline expectation, and prefix the input with a letter (`a****`) to force the level under test; write rendered-output expectations from the escaping rule ("every text/code/attribute char is escaped"), not by eye.
