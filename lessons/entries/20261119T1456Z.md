# Lesson 20261119T1456Z

## Task
Level 20 capstone: `ae.hm`, Hindley-Milner principal-type inference (lexer/parser, Algorithm W with a single mutable substitution, occurs check, let-generalisation, monomorphic `let rec`, positioned errors). Overlap check: benchmark tasks j07-expr, j28-script and j35-minisql evaluate programs; this task only infers types by unification, so no core algorithm matches a benchmark task.

## What worked
- Writing the known-answer table, error-position tests and generalisation traps before any code; all 38 hand-written tests passed on the first run.
- A type-directed random term generator (terms built from a target type, so all are well typed) with oracles independent of the engine: a one-way instance matcher, let-inlining preserving the principal type, print/parse round trip, and "`(t) + 1` is a MISMATCH unless t is Int".
- Two mutation kill checks (generalise ignoring the environment; disable the occurs check) both made tests fail, so the tests can fail.

## What failed
First run: 5 of 46 tests failed with `ParseException`. The *generator* emitted `let`, `if` and lambda terms without parentheses in argument and operand positions (`(snd if ...)`).

## Root cause
Test-side string generator ignored the grammar's rule that `let`/`if`/lambda are only valid at expression level, not as application arguments. The engine was correct; the property tests reported parse errors, not type errors.

## Rule learned
When a test generator emits source text, parenthesise every non-atomic production at generation time and add a "generated text always parses" check first, so generator bugs are separated from engine bugs. For HM-style code: assert an exact result for the generalisation trap (outer lambda variable captured by a let-bound function) and run a mutation that generalises everything.
