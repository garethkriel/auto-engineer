## Task
Level 20 capstone: `ae.mvcc`, an in-memory MVCC key-value store (snapshot and serializable transactions, range scans, vacuum). Overlap check against `benchmark/java/` (kvlog, minisql, cache, ratelimit...): none implements multi-version concurrency control.

## What worked
A seeded differential test against a naive "copy the whole map at begin" model validated commit timestamps, conflicts and scans together over 60 seeds x 400 steps. Three mutations (watermark = last commit, disabled range validation, keeping the dead tombstone) failed 4, 2 and 1 tests. Final run: 28 tests, 0 failures, concurrency class run 6 times clean.

## What failed
First run: 1 failure, a test defect. `firstCommitterWinsOnSameKey` asserted `activeTransactions() == 0` after a verification read `store.begin().get("x")` that itself leaked an open snapshot, so the count was 1. Also, my first draft contained nonsense placeholder expressions (a phantom test with `- 0` arithmetic, a "fresh" helper) that I rewrote before running.

## Root cause
In a store where open transactions are observable state (active count, vacuum watermark), every `begin()` in test code registers a snapshot; peeking at state with a throwaway `begin()` changes the very thing being asserted. Placeholder expressions came from writing tests while still deciding the semantics (read-only serializable commits).

## Rule learned
When a resource handle's lifetime is observable (active transactions, pinned snapshots, open files), do every verification read inside try-with-resources and assert the count before the verifying read; decide edge semantics (read-only commit, empty range) in TASK.md before writing the test, so no placeholder expression is needed.
