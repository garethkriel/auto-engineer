## Task
Level 20 capstone: `ae.spatial.SpatialIndex`, a point quadtree service with range, radius, k-nearest, polygon and DBSCAN queries and CRC-checked canonical snapshots. Overlap check against `benchmark/java/` names: none is spatial or geometric (`j23-segtree` is 1-D array ranges; the only "nearest" hit is variable scoping in `j28-script`).

## What worked
Fixing ordering in TASK.md first (every result sorted by (distance, id), nodes expanded before tied entries in the best-first kNN queue) meant engine and oracle agreed on all 37 other tests the first time. An invariant checker (`checkInvariants`: counts, leaf bounds, collapse rule, tree == id table) ran after every random insert/remove/move. Three mutants (node/entry tie order in kNN, collapse threshold `<=` to `<`, radius `<=` to `<`) failed 1, 3 and 4 tests, so those tests can fail.

## What failed
Attempt 1: 37 of 38 passed. `polygonMatchesBruteForceCrossingNumber` failed in round 2 with one extra point (`q96`) in the engine's answer.

## Root cause
The test oracle, not the code, was wrong. It avoided vertex grazing by casting the ray at `y + 0.25`; on a slanted edge that moves the x-intersection, so a lattice point very close to an edge flipped sides. I had not proved the shifted ray was equivalent to the half-open rule.

## Rule learned
When writing an independent oracle for a geometric predicate, decide it from exact sign tests (cross-product orientation with a half-open y rule) on integer-lattice inputs, never by perturbing the input to dodge degenerate cases; and suspect the oracle first when a differential test fails on a single near-boundary item.
