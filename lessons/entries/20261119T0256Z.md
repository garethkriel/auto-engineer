# Lesson 20261119T0256Z

## Task
Level 20 capstone: `ae.minisql`, a mini SQL database (lexer, sealed-AST parser, 3VL evaluator, joins, grouping, ordering, atomic statements, transactions) built test-first.

## What worked
- Writing grammar and semantics (NULL ordering, alias vs column in ORDER BY, empty-input aggregates, atomicity) in TASK.md first made every test a literal expectation.
- A differential test with an independent 3VL oracle over random predicates (AND/OR/NOT/BETWEEN/IS NULL) validated WHERE, UPDATE and DELETE counts, ORDER BY and GROUP BY in one go. Three hand-made mutants (IN with NULL, null ordering, LEFT JOIN null extension) were all caught.
- Row lists replaced rather than mutated made atomicity and transaction snapshots trivial.

## What failed
1. Compile error: `List.of(row)` with `Object[] row` is parsed as the varargs array, giving `List<Object>`. 2. Tests: `r(null)` with a single null argument passes a null array to a varargs helper; and the differential UPDATE-then-DELETE ran the second predicate against rows the first had changed. The run took 3 attempts.

## Root cause
Varargs/array overload traps (library and test helper) and a test sequence whose second step depended on state mutated by the first.

## Rule learned
- Never pass an array to `List.of`/`Arrays.asList` expecting a one-element list: use `Collections.singletonList`; make variadic test helpers take `(Object first, Object... rest)` or cast a lone null `(Object) null`.
- In randomized update/delete tests, run each mutating statement in its own transaction and roll back, so predicates always see the original data.
