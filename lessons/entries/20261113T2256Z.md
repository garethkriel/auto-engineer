Level 3 practice: immutable `TextTable` formatter (Comparator stable sort with non-numeric-last rule, StringBuilder rendering, Math.max widths).

## What worked
Writing the "non-numeric sorts last in both directions" rule as a hand-written comparator branch (instead of `reversed()`, which would flip the non-numeric group to the front) passed first time. `List.sort` is stable, so tie order needed no extra code. Treating non-finite doubles (`NaN`, `Infinity`) as non-numeric avoids comparator contract trouble.

## What failed
Maven hit the transient "Could not find artifact" error again (retried with `-U` and sleeps; not counted). One test failed on the first real run: `lastLeftColumnHasNoTrailingSpaces`.

## Root cause
My expected string used a separator `--+---...` and header `k` as if the first column were 1 wide, but its longest cell is `22`, so the column is 2 wide (header ` k`, separator `---+-`). The code was right; the expectation was computed by eye from the wrong widths.

## Rule learned
For formatted-output tests, write the fixture rows first, mark each column's max cell length, and derive padding/separators from those widths before typing the expected string; prefer fixtures whose widest cells are in distinct columns so a width mistake cannot cancel out.
