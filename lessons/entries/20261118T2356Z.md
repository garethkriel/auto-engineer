## Task
Level 20 capstone: `ae.vfs`, an in-memory POSIX-like filesystem (inodes, hard links, symlinks, permissions, quota, snapshots, `fsck`). Overlap check against `benchmark/java/`: none of the 35 task names (roman ... minisql) is a filesystem or path-resolution task; `glob-matcher` and `dir-snapshot-diff` skills operate on real files, not an inode model.

## What worked
One `walk(path, followLast)` routine (a deque of pending components so symlink targets are pushed in front, a stack of directories for `..`, a hop counter for ELOOP) served all operations, so symlink and permission rules lived in one place. Tests written first: an errno table, a rename matrix, a permission matrix, a quota-atomicity test, a snapshot test (checks independence, link identity and double restore), plus a seeded differential test of 40 seeds x 300 steps against a naive path-map model, with `fsck()` and a full state comparison after every step. Five mutations (drop dir-into-self check, drop parent re-pointing in snapshot copy, no nlink increment, wrong unlink-free condition, ignore group bits) were each caught.

## What failed
Nothing failed at the build level: 17 tests passed on the first `mvn -q -B clean test`. While drafting I wrote two junk test lines (a tautological `"/d".equals("/d") ? ... : ...` expression and `assertEquals(1, used - 1)`) and caught them on re-read before running, then replaced them with concrete literals.

## Root cause
Drafting tests in one long heredoc made me emit placeholder expressions when I lost track of the intended assertion; the existing rule about rereading drafts for placeholder expressions caught it, not the compiler.

## Rule learned
For stateful hierarchical structures (filesystems, trees with parent pointers), keep an invariant checker (`fsck`) and a naive path-keyed model and compare after every random step; snapshot/copy code must be tested for pointer re-wiring (parent pointers, shared hard-link identity) by mutating the copy and the original independently, and by restoring the same snapshot twice.
