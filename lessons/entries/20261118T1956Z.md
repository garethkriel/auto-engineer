## Task
Level 20 capstone: `ae.jobs`, a durable job scheduler (write-ahead journal with CRC lines, dependency DAG, exponential-backoff retries, cascade cancel, crash recovery). Overlap check against `benchmark/java/` (cron, queue, topo, minisql, ratelimit...): no shared core algorithm.

## What worked
State as a fold over events with append-before-apply made recovery trivial; the crash-at-every-append sweep, truncate/flip-every-byte loops and a seeded oracle test caught design questions early. A mutation (removing the recovery step) failed 2 tests, so the tests can fail. Final run: 33 tests, 0 failures.

## What failed
First test run had 3 failures, all test defects: (1) I guessed the append count as 22, the real count is 16 (5 submits + 2 + 4 + 2 + 2 + 1); (2) I expected `delayAfter(2)` of base Long.MAX/2 to be Long.MAX, but 2*base is MAX-1; (3) the double-crash sweep expected success although each crash consumes an attempt, so b legitimately died after 3 attempts. One compile error (multi-catch of related exception types) came before.

## Root cause
Expectations were written from a rough mental model instead of derived from the event sequence, and the interaction "crash consumes an attempt" was not in the expectations. Also the scheduler runs other ready jobs (d) between a retry's failure and its backoff, so my assumed append order was wrong.

## Rule learned
For recovery sweeps, write down the exact event sequence per job (including interleaving with other ready jobs) before pinning counts, and give multi-crash tests a retry budget of failures + crashes + 1; document in a separate test that crashes consume attempts.
