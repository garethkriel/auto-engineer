## Task
Level 20 capstone: multi-decree Paxos replicated log in `ae.paxos` (practice/java/20261125T1456Z): ballots, acceptor rules, phase-1 recovery with NOOP gap filling, heartbeat/forward/sync, and a seeded fault-injecting `Cluster` with an agreement/validity/promise-monotonicity checker. Overlap check: compared with all 35 `benchmark/java` directory names; none is a consensus task.

## What worked
Writing the rule list (quorum, acceptor, recovery, durable state) into TASK.md first and the tests before code: 28 of 29 tests passed on the first compile, including 80 chaos runs. A scripted unit test (hand-fed `Promise` messages) pins "adopt highest ballot, NOOP for gaps, own command in a fresh slot". A 19-mutant pass killed 18; the survivor exposed a real test gap.

## What failed
Run 1: one chaos seed never converged after healing: a node had missed the last `Decide`s because the leader that decided them crashed, and nobody re-sent them. Run 2: my new catch-up test blocked only one link, so the node learned through another peer and the "still behind" assertion failed. The surviving mutant (`Accepted` not checked against the leader's current ballot) was unobserved by any test.

## Root cause
(1) Learner liveness was missing from the design: Paxos decides values, but telling every replica is a separate anti-entropy job. (2) Fixture too weak: a partial block does not isolate a node. (3) Late acks of an old term only matter when a leader re-proposes the same slot, which random runs rarely hit.

## Rule learned
For consensus code add an explicit learner catch-up path (Sync) and a post-heal convergence test with the deciding leader crashed. Isolate a node fully (all links) when a test needs it behind. For every "ignore messages from another ballot/term/epoch" guard write a direct unit test that delivers one stale message and asserts no effect, because chaos runs seldom reach it; mutation-check every such guard.
