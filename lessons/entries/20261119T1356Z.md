# Lesson 20261119T1356Z

## Task
Level 20 capstone: `ae.gc.Heap`, a simulated word heap with a coalescing first/best-fit allocator, iterative mark-sweep GC, sliding compaction, stable handles and free listeners. Overlap check against `benchmark/java/` names (incl. `j19-allocate`, which is resource allocation): no memory-allocator or GC task, so no overlap.

## What worked
Fixing the layout (`[handle][data][refs]`), the tie-break rules and the "carve from extent start" rule in TASK.md let every placement test use literal addresses. A seeded differential test against a naive reachability model, with `checkInvariants()` (tiling of blocks and extents) after every step, passed first time. Mutants (best-fit tie `<` to `<=`, disabling left-neighbour coalescing) failed 1 and 10 tests.

## What failed
First run: 22 of 24 passed. `bestFitTiesGoToLowestAddress` expected 2 extents but saw 3; `freeingBetweenLiveBlocksKeepsSeparateExtents` expected largest extent 6 but saw 4.

## Root cause
Both were wrong hand-computed expectations, not code defects: in the first test the last allocation (`e`) was left unrooted, so the GC freed it too; in the second I mistook the tail extent `[6,10)` (4 words) for 6. I tracked rooted/garbage sets and tail sizes in my head instead of writing a running layout.

## Rule learned
For allocator/GC fixtures, write the layout as a comment table (address, size, live/garbage) next to the setup, and root or release every object explicitly; derive extent counts and sizes from that table before asserting.
