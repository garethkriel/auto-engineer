# 20261119T2256Z

## Task
Level 20 capstone: `ae.rsync`, rsync-style delta sync: rolling weak checksum, per-block SHA-256 signatures, copy/literal deltas, CRC-sealed wire formats, a verifying patcher and an atomic directory sync. Overlap check: the nearest benchmark directory is j18-diff (line LCS); this task is byte-level rolling-hash matching and shares no core algorithm with any `benchmark/java/` entry.

## What worked
- Writing the wire layouts (offsets of every field) as comments in the test file before coding made the "reseal with a valid CRC, then corrupt one field" tests exact and each failure message-specific.
- A real weak-checksum collision built by construction: a second difference (+1, -2, +1) on three bytes leaves both sums unchanged, so `{5,5,5}` and `{6,3,6}` collide. The test asserts the weak values are equal first, then that no copy is emitted. Removing the strong-hash check made it fail.
- Rolling checksum tested against recomputation at every position for several window sizes, plus all-0x00/0xFF data; dropping the `length * out` term was caught by 6 tests.
- Literal-cost bounds (`k <= literals <= k + blockSize` for one insertion) check algorithmic quality, not just round trip. 57 tests passed on the first full run.

## What failed
- Nothing failed in the final run. During design I nearly keyed the block index on the weak checksum alone; the short last block would then have been compared against full-size windows.

## Root cause
- A short final block has a different window length, so a rolling hash that only encodes content is ambiguous without the length. This is a design trap, not a bug that was hit.

## Rule learned
- For rolling-hash block matching, key candidates on (weak, length), accept only after a strong-hash match, and let the short tail match only when exactly that many bytes remain; test with a constructed weak collision and assert the weak values are equal before asserting no copy.
- For checksummed formats, put a layout table in the test comment and test structure checks with resealed images (valid CRC, one bad field), asserting the message names the field.
