## Task
Level 3 practice: `InvertedIndex` using TreeMap/TreeSet, Comparator-based `topTerms`, StringBuilder `render`.

## What worked
Choosing sorted collections (`TreeMap`, `TreeSet`) removed all explicit sorting for `search` and `render`; `Collections.unmodifiableSortedSet` made results safe. Chained `Comparator.comparing(...).reversed().thenComparing(naturalOrder())` gave a deterministic tie-break.

## What failed
The first run hit a transient Maven "Could not find artifact" error (not counted as an attempt; `-U` retries fixed it). Then one test failed: `topTermsLargerThanVocabularyReturnsAll` expected 8 terms but the corpus has 7.

## Root cause
I counted the vocabulary of the fixture by hand ("the quick brown fox / the lazy dog the end / quick quick dog") and miscounted by one; the code was right. Asserting a bare size made the miscount easy; listing the exact terms exposes the mistake.

## Rule learned
When expecting the size of a derived collection, assert the full expected contents (list the terms) rather than a hand-counted number, and re-derive the fixture's contents before running.
