# Lesson 20261126T1557Z: RFC 3986 URI toolkit

## Task
Level 20 capstone `ae.uri`: strict URI parser, section 5.2 resolver, normaliser, relativizer, percent codec, query params. Overlap check: `benchmark/java/` names j01-roman..j35-minisql listed; none is a URI/URL tool.

## What worked
- RFC section 5.4 examples as literal tables, rejection tests as pairs (bad input + control differing by one defect), and a generator validated first (`generatorProducesOnlyValidUris`).
- A single `build(...)` factory that adds `/.` or `./` so recomposed text always re-parses to the same components.
- 22-mutant pass: 20 killed, 2 equivalent (port length guard masked by the 65535 bound; `colon <= firstDelim` can never hold).

## What failed
Five runs were needed; the production code changed only once (IPv6 left-side IPv4 tail). Every other failure was the JDK oracle disagreeing with the RFC: it collapses `//`, keeps `/.`, returns absolute refs untouched, drops an empty authority, normalises an empty-ref base path. My own test wrongly rejected `?` in a fragment. The mutation pass found two test gaps (relativize with dot segments, IPv4 leading zero).

## Root cause
I picked `java.net.URI` as oracle without first listing where it deviates from the RFC, and discovered the deviations one rerun at a time, exceeding the 3-attempt budget. Also tested the grammar from memory, not from the ABNF.

## Rule learned
- Before using a JDK class as differential oracle, write down its known deviations from the spec and restrict the generator to the conforming subset up front; if it disagrees with a literal from the RFC, the RFC wins.
- Write grammar tests from the ABNF (which characters each component allows), not from intuition (`?` and `/` are legal in query and fragment).
- A "must not change" guard (dot segments in relativize) needs a fixture where applying the algorithm anyway gives a different answer.
