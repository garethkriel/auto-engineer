## Task
Level 20 capstone: `ae.peg`, a PEG engine (grammar text parser, static analysis, packrat interpreter, parse trees, farthest-failure errors). Overlap check: `benchmark/java/` has expr, json and regex tasks, but this round builds a grammar interpreter and never evaluates expressions, builds JSON values or implements a regex engine; no other benchmark name is related. The test oracle uses `java.util.regex` only as a reference.

## What worked
- A regex oracle for PEG: every unit becomes an atomic group (`(?>A|B)`, `(?>(?:X)*+)`, lookahead), so the regex cannot backtrack into a unit and matches PEG's committed choice and possessive repetition. 1500 random expressions (accepted/rejected mix and match/no-match counts asserted) agreed on the first run.
- Keying the memo by (rule, position, inside-predicate) keeps silent lookahead failures from hiding expectations later; a dedicated test (`!Item 'q' / Item`) plus a mutation that dropped the flag was caught.
- Kill checks: dropping the silent flag failed 1 test, making repetition give back one char failed 14, ignoring nullability in left-call computation failed 17.

## What failed
Three red runs, all test-expectation defects, no engine bug: (1) my JSON-ish grammar rejected `[ ]` (whitespace is consumed inside `Value`, not after `[`), `'a'? 'a'` on `a` is -1 not 1 (`?` is possessive), my "blow-up" grammar did not blow up on `a` inputs; (2) column of an unterminated group on line 2 off by one, a bare `B 'b'` after a rule is a reference so the error is "undefined rule"; (3) cycle expectation `A -> N -> A` for a rule where N is only a nullable prefix, not part of the cycle.

## Root cause
Hand-derived expectations for PEG behaviour were written from regex/backtracking intuition (`a?a` matches `a`, a blow-up needs the first alternative to fail only after the shared sub-rule succeeded). Error-position literals were counted by eye. I also wrote the engine before the tests this time, which let the implementation shape the expectations.

## Rule learned
For PEG/ordered-choice code, derive every table row with "commit, never retry" semantics (possessive `*`/`?`, choice fixed after first success) and sanity-check the table against an atomic-group regex before running; build performance tests so the first alternative fails only after the shared sub-rule succeeds, and assert plain vs memo evaluation counts; compute error columns with `indexOf`/`length()+1` instead of counting by eye. Write tests before the implementation.
