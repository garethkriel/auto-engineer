# Lesson 20261119T0456Z

## Task
Level 20 capstone: `ae.locks.LockManager`, a deterministic non-blocking multi-granularity lock manager (IS/IX/S/SIX/X, path hierarchy with intention locks, FIFO queues, upgrades, deadlock detection with youngest-victim abort, unlock/2PL). Overlap check against `benchmark/java/`: `j26-rwlock` is a blocking one-object reader/writer lock and `j15-topo` is ordering; neither has modes, hierarchies, upgrades or deadlock victims.

## What worked
Making the API non-blocking (GRANTED/WAITING/ABORTED plus an `Events(unblocked, aborted)` record) made every schedule reproducible, so 25 scenario tests could use literal expectations. A package-private `checkInvariants()` (compatible holders, intention ancestors, one-to-one queue/BLOCKED match, no grantable queue head, acyclic wait-for graph) ran after every operation of 300 seeded random workloads, next to an independent model of "who is BLOCKED" built only from reported outcomes. Mutation checks: victim-oldest failed 6 tests, dropping FIFO 4, wrong IX-join-S 5, no queue-edge in the wait-for graph 1, upgrades-to-front 1.

## What failed
Attempt 1: 36 of 37 passed; `randomWorkloadsActuallyExerciseWaitsAndDeadlocks` failed with `waits=60`. Two mutants initially survived: the FIFO-only wait-for edge and the ordering of several waiting upgrades.

## Root cause
The failing test was my bug: the counter I asserted on (`model.waits`) was never incremented in that loop and the loop never committed, so it measured one blocked txn per seed. The surviving mutants were because my first "queue-edge deadlock" scenario also contained an ordinary holder edge in the cycle, and because two waiting upgrades on the same resource normally deadlock with each other (so the order test needs IS->IX upgrades blocked only by a third holder).

## Rule learned
When a test asserts that a random workload "actually exercises" a behaviour, increment the counter at the point of the event and print it in the message; and for every ordering/edge rule in a graph algorithm, write the scenario so that removing that single rule changes the answer (mutate it and confirm the test fails) rather than trusting that a cycle test with several kinds of edge covers each kind.
