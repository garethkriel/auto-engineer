## Task
Level 20 capstone: `ae.prolog`, a Prolog-subset engine (operator-precedence parser, iterative SLD resolution with cut barriers, if-then-else, `\+`, `call/N`, `findall`, assert/retract, overflow-checked arithmetic, prelude library). Overlap check: `benchmark/java/` j01-j35 has no logic-programming, unification or cut task (nearest j07-expr and j35-minisql share no core algorithm); `skills/java/datalog-engine` is bottom-up with no cut, lists or arithmetic.

## What worked
- An iterative machine (continuation list + choicepoint stack + trail) with the cut barrier stored in each continuation frame; `->`, `;`, `\+` all reduce to `Alt` choicepoints plus a private `$cut(B)` goal. 200000-step recursion and 50000-element lists ran with no stack issue.
- Differential tests against Java: exact arithmetic with `Math.*Exact` (generator reported 300+ values and 100+ errors, so both outcomes are exercised), list splits, permutation counts, quicksort vs `Collections.sort`, parse(format(t)) round trip on 3000 random terms.
- A 24-mutant hand run (per-mutant 100-150 s timeout, file restored in `finally`). First pass: 7 survivors, 6 real gaps (cut inside an if-condition, cut in a disjunction's else branch, first-argument indexing determinism, partial-binding undo after a failed head, `between` lower bound, `==` vs unify, `xfx` non-associativity). Each got one dedicated test and was killed on rerun.

## What failed
- Attempt 1: `mvn test` died with `Java heap space` and no test report. Cause 1: my own test `length(L,N), N < 2` with `all(q, 3)` asks for a third answer that does not exist, so the engine searched forever. Cause 2 (found while isolating): `X = f(X)` without the occurs check makes a cyclic answer, and copying it for the `Solution` never ended.
- One new test expected `g(z(1),V)` to be determinate; indexing only looks at the functor, so one choicepoint is correct. The expectation, not the code, was wrong.

## Root cause
Non-terminating queries and cyclic terms turn a failing test into an out-of-memory crash of the whole surefire fork, which hides every other result. The first cause was an unchecked assumption in a test about how many answers a query has; the second was a missing size guard on a deep copy of terms that can be cyclic.

## Rule learned
- When `mvn test` dies with `Java heap space` and no report, run each test method separately in a loop (`-Dtest=Class#method`) to find the culprit before touching the code.
- For logic/search engines: a test that asks for N answers must be checked to have at least N; give every deep copy or traversal of possibly cyclic data a node budget that throws a clean error, and test it.
- For machines with cut or backtracking, kill-check each barrier: write a test where the cut sits inside a condition, a negation, an else branch and a called goal, with an outer choicepoint that must survive; and assert a choicepoint count to prove indexing keeps deterministic tables deterministic.
