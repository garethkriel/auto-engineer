# Lesson 20261117T2156Z

## Task
Level 14 storage: `ae.tsblock`, a compressed, checksummed time-series block file (varint delta-of-delta blocks, CRC32 per block, CRC-protected footer index, temp file + atomic move). Overlap check against `benchmark/java/` (j29-kvlog is a key/value log; this is a columnar block file with compression and a range index) found a different core algorithm.

## What worked
- Writing the corruption tests first: every-length truncation and every-byte-flip loops drove the open-time validation (magic, trailer offset range, index length, index CRC, entry ordering) and the per-block checks (CRC, count, min/max agree with index).
- Wrapping 64-bit subtraction/addition for deltas, so Long.MIN/MAX timestamps round trip with no overflow branch.
- A `blocksDecoded()` counter made index pruning observable; range tests compared to a brute-force filter with random half-open ranges including empty ones.

## What failed
Attempt 1: test compile error, `Varint.readSigned` throws a checked `CorruptFileException` and the test method lacked `throws`. Fixed in attempt 2; all 24 tests passed.

## Root cause
I made the exception checked (extends IOException) after writing a helper test that called the reader inside a plain `void` test method; I did not check which test methods would call throwing APIs before the first compile.

## Rule learned
When an API signals corruption with a checked exception, add `throws` to every test method that calls it directly, and prefer testing helpers via `assertThrows` lambdas; for binary formats always include an exhaustive truncation loop and a flip-every-byte loop asserting "exception or identical data", never silently different data.
