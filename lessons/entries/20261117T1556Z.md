Nothing failed at run time. During test writing I spotted two weak assertions of my own (a ternary that could never fail, and a `Map.of(...).size()` comparison) and replaced them before running.

## Root cause
Writing expectations quickly in prose-like form produces tautologies. Both defects came from hedging on an expected value instead of computing it.

## Rule learned
For 64-bit arithmetic, take every expected value from an independent engine (`BigInteger`) or a published literal, never from an expression that can be true by construction; scan new tests for ternaries and `.size()`-only assertions before the first run. Use `Math.multiplyHigh` to keep the common mulMod path allocation-free and fall back to BigInteger only when the product exceeds 63 bits.
