# 20261119T1556Z

## Task
Level 20 capstone: SWIM membership/failure detection (`ae.swim`): ping and ping-req probing, suspicion with incarnation refutation, piggybacked gossip, a seeded in-process network simulator and a per-tick safety invariant checker. Overlap check: no benchmark task (j01-j35) is a failure detector or gossip protocol (j34-vclock is vector clocks only).

## What worked
- A pure state machine (`tick(now)` / `receive(msg, now)` return messages) allowed hand-driven unit tests with exact tick numbers (suspect at t=8, DEAD exactly 10 ticks later) before any simulation existed.
- Safety invariants checked after every tick, plus `debugForce` test hooks proving the checker throws for resurrection, decreasing and forged incarnations.
- Two mutations (targeted suspicion payload removed; refutation using `>` instead of `>=`) each failed 2-5 tests, so the tests can fail.

## What failed
Attempt 1: 3 of 49 tests failed. (a) The partition test ended with a node DEAD in a lossless network, (b) a 15%-loss run buried a live node at t=40, (c) the decreasing-incarnation checker test saw no violation because gossip overwrote the forced value during `step()`.

## Root cause
(a, b) The test config used a suspicion timeout of 24 ticks (3 probe periods), shorter than the time gossip needs to reach a suspected node in an 8-node cluster, and a 20-tick partition let the isolated node's own suspicions expire; that is a wrong test parameter, not a protocol bug. (c) Calling `step()` between forcing state and checking lets the protocol repair the corruption; the checker must be invoked directly (`checkInvariants()`).

## Rule learned
Choose protocol timeouts from the dissemination model before writing simulation tests (suspicion timeout >= several probe periods, partitions shorter than the shortest suspicion timeout, probe period >= direct timeout + indirect round trip in ticks), and test an invariant checker by calling it directly after corrupting state rather than through a stepping method that can self-heal.
