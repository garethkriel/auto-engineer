# Lesson 20261126T1657Z: LR parser generator (SLR / LALR / LR1)

## Task
Level 20 capstone `ae.lr`: grammar analysis (FIRST/FOLLOW), SLR, LALR(1) and canonical LR(1) tables with conflict reports, and a table-driven parser. Overlap check: `benchmark/java/` names j01-roman..j35-minisql listed in TASK.md; j07-expr and j28-script evaluate with hand-written parsers, none builds parser tables from a grammar.

## What worked
- One automaton builder (items carry a lookahead or `""`) serves all three modes: SLR = LR(0) states + FOLLOW, LR1 = canonical, LALR = canonical merged by core. This made the theorem "LALR states == LR(0) states" a free property test over 400 random grammars.
- A language oracle with no LR knowledge (least fixed point of sentence sets up to a length cap) checked the parser on every string over the alphabet up to length 6, plus tree validity and the viable-prefix property of canonical LR(1) errors.
- Dragon-book literals (12/12/22 states, `S->CC` 7/7/10) independently confirmed the construction on the first run.
- 21-mutant pass: 21 killed, 0 survivors.

## What failed
Two runs. Run 1 had two test defects, no production bug: (1) I expected LALR state 4 (`C -> d .`) to reduce only on {c,d} although LALR merges it with the `d` reached after a `c`, whose lookahead is `$`; (2) I guessed "accepted > 100" for the expression grammar, but only 15 sentences have length <= 6.

## Root cause
Hand-written expectations came from the canonical LR(1) picture while the table under test was LALR (merged lookaheads), and a count threshold was guessed instead of derived. Both are the "expected values are derived, not guessed" mistake again.

## Rule learned
- When a test asserts a lookahead set in a merged (LALR) state, check against the mode: exact lookaheads belong in `Mode.LR1` assertions; the LALR expectation is the union over merged states (here it equals FOLLOW). Test the difference with both modes side by side.
- Derive "number of accepted strings" literals by enumerating the language by length (1 + 3 + 11) in a comment before writing the assertion.
- The validator's level range is 1-20 (the older rule about capping at 10 no longer applies); record the level reported by `tools/curriculum.py`.
