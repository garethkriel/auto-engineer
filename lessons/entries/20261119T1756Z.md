# 20261119T1756Z: probabilistic sketches (Bloom, Count-Min, HyperLogLog)

## Task
`ae.sketch`: Bloom filter, Count-Min sketch and HyperLogLog over a seeded 64-bit hash, with merge and CRC-sealed
serialization. Overlap check: none of the `benchmark/java/` task names (roman ... minisql) is a sketch task;
Count-Min is a frequency table over opaque keys, not word-frequency/top-k.

## What worked
- Separating exact guarantees (no false negatives, never underestimate, merge equals sketch of union) from statistical
  ones (seeded data, upper bound plus a lower sanity bound so a degenerate filter cannot pass).
- Computing every `Math.addExact` result into locals before mutating the table, with tests asserting the sketch is
  byte-identical after a failed `add`/`merge`.
- Crafted re-sealed images via a package-private `Codec.seal` to test structural validation behind the CRC.
- Final run: 41 tests, 0 failures.

## What failed
Attempt 1: one test error, `bad magic`, in `resealedBadPrecisionOrRegisterIsRejected`.

## Root cause
A test defect, not a code defect: while building a crafted image I left a stray `over.put(0, (byte) 0)` from an earlier
draft that overwrote the first magic byte, so the loader rejected the image for the wrong reason before reaching the
register check. I also wrote the tests after the implementation this round, which let such draft debris through
without a failing-first signal.

## Rule learned
When a test expects rejection for reason X, assert on the exception message (or build a control image that differs only
by the one defect and must load), so a rejection for an unrelated reason fails the test. Write tests before the
implementation, as the loop requires.
