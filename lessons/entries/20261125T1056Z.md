## Task
Level 20 capstone: `ae.proto` (practice/java/20261125T1056Z), a protobuf-style wire codec: varint/zigzag, text schema parser, immutable dynamic `Msg`, strict `Codec` with packed repeated fields and byte-exact unknown-field preservation. Overlap check: compared the 35 `benchmark/java` directory names one by one (roman, wordfreq, lru, csv, intervals, lcs, expr, graph, bank, counter, streams, fileindex, ratelimit, json, topo, ranges, cache, diff, allocate, cron, sheet, regex, segtree, queue, bizhours, rwlock, primes, script, kvlog, miniserver, ranked, fsm, pricing, vclock, minisql); none is a schema-driven binary codec.

## What worked
48 tests passed on the first run (3 fuzz, 24 codec, 10 schema, 11 varint). Tests came first, from three independent sources of truth: public protobuf guide hex literals, an in-test reference encoder built on BigInteger (zigzag from its definition, not from the bit trick), and fuzzing where every truncation and bit flip must either decode (and then re-decode stably) or throw `DecodeException` with an in-range offset. A 12-mutant pass (overflow limit, zigzag shift, tag width, group wire types, depth limit, negative length, int32 truncation, packed branch, unknown re-emit, last-wins clear, uint32 range, reserved range) killed all 12.

## What failed
Nothing failed in the run. One design smell was left: `Codec.decodeMessage` reads fixed-width values through a `payloadOrFixedStart` helper that recomputes the start offset from the end position, which is harder to read than carrying the start explicitly.

## Root cause
No defect to root-cause. The things that usually go wrong in this kind of codec were prevented by writing the rule table first: field-number zero vs wire type check order, 10-byte varint overflow, unsigned length compared as signed, and "known field with wrong wire type" being unknown rather than an error.

## Rule learned
For wire formats, pin every redundancy with one literal vector and one control that differs only by that defect (10th varint byte 1 vs 2; field 1 as varint vs length-delimited), take the oracle from a different formulation than the code (BigInteger groups, zigzag by definition), and let fuzzing assert an exception whitelist plus a stability property (decode, encode, decode gives an equal message), with minimum counts of both outcomes so the fuzz cannot go vacuous. Carry offsets forward as explicit variables instead of recomputing them from end positions.
