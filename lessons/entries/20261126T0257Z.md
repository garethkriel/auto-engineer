# 20261126T0257Z — text encodings toolkit (ae.utf)

## Task
Strict/lossy/streaming UTF-8 (WHATWG), UTF-16 with BOM detection, RFC 3492 Punycode, verified against JDK charsets and java.net.IDN. Overlap check: read `benchmark/java/` names (j01-roman … j35-minisql); none is an encoding task.

## What worked
- One state machine (lead byte → needed count + allowed first-continuation range) serves strict, lossy and streaming modes, so chunking invariance is almost free; tested by random splits including empty chunks.
- Exhaustive enumeration of all sequences of length 0..4 over a 26-byte boundary alphabet (≈480k inputs) compared with the JDK decoder.
- A mutation pass (18 mutants) found 3 test gaps; closed with targeted tests.

## What failed
- Attempt 1: two oracle problems, not code defects. The JDK lossy decoder emits ONE U+FFFD for `ED A0` while the WHATWG table gives two (ED is rejected, A0 reprocessed). `java.net.IDN.toASCII` throws on mixed-bidi labels (Arabic + Latin).
- My first "overflow" tests used `z` digits, which only produced "truncated number" (digit 25 is below the threshold 26 after k=108), so they did not exercise overflow at all; a message assertion exposed it.
- Two weak ternary assertions slipped in (`... ? 2 : -1`).

## Root cause
Treating a library as ground truth without first checking the spec row it implements; and writing an "overflow" input without computing which digit values keep a variable-length integer going (needs d >= threshold at every k, e.g. `9` = 35).

## Rule learned
When a JDK/library oracle disagrees on a corner, derive the spec's answer by hand, keep the oracle for everything else, and exclude only the proven divergence with a comment naming it. For variable-length number decoders, build overflow inputs from digits that can never terminate the number and assert the error message, so a "truncated" error cannot pass for "overflow".
Survivors: `Punycode` `i > MAX` / `w > MAX` widened to `MAX*4` are equivalent on all inputs (still far below long overflow and the final scalar-range check masks the rest); `Utf16` `i + 3 >= length` vs `>` is equivalent because length is even and `i + 3` odd.
