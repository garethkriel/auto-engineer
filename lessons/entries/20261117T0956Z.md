## Task
Level 10 (concurrency): `batch.MicroBatcher<T,R>`, which groups single `submit` calls into size-or-time batches for one bulk function, with an injectable `Scheduler`. Overlap check vs `benchmark/java/` names: none is batching (j24-queue is a blocking queue, j13-ratelimit a token bucket, j03/j17 caches).

## What worked
Making time an interface (`Scheduler`) let 15 of 17 tests run on a manual clock with no sleeps, so timing assertions (99ms not due, 100ms due) were exact. A generation counter bumped whenever a batch is detached made stale timers harmless, and a test with a scheduler that ignores cancellation proved it independently of timer cancel. Tests passed 6 consecutive runs.

## What failed
CI `tests` check (validate_round) failed on the first push: `M skills/java/INDEX.md: only maintenance or proposal PRs may change this`. I had added an INDEX row for the new skill.

Attempt 1 did not compile: my `sed` range delete of a throwaway test method stopped at the method's closing brace but left its `@Test` annotation above, giving "illegal start of type".

## Root cause
Editing generated test code with a line-range `sed` instead of the Edit tool; the range started at the method name, not at its annotation. Production code was fine.

## Rule learned
A practice round must only ADD files: never edit `skills/java/INDEX.md` (maintenance adds index rows); check `git diff --name-status <merge-base>` shows only `A` lines before pushing.

Also: Remove code with the Edit tool (or write the file correctly the first time); never use a `sed` range delete that begins at a method name, because the preceding annotation stays behind. Dropping a placeholder test is better done by not writing it.
