# 20261126T2056Z practice: compiler middle-end toolkit (ae.cfg)

## Task
Three-address IR parser/validator, CFG, dominators (Cooper-Harvey-Kennedy) with frontiers, natural loops and reducibility, liveness, liveness-driven DCE, interference graph and Briggs optimistic colouring with register renaming. Overlap check: read `ls benchmark/java` (j01-roman ... j35-minisql); none is a CFG/dataflow/register-allocation task (j08-graph is plain search, j28-script an interpreter); `grep -ril "dominator\|liveness" skills` found nothing relevant.

## What worked
Every analysis got a definition-level oracle written differently from the production algorithm: dominance by "removing a cuts b off", frontiers from the textbook definition, loop bodies by avoidance reachability, reducibility by T1/T2 reduction, liveness by brute-force path search, DCE and register renaming by interpreter equivalence (plus a negative control that merges registers and must be detected). Hand-derived literals for the allocator (k=3 and k=2 on a 5-variable function, a 4-cycle, K4) matched the code on first run. 56 tests, `survivors: []` on a 53-mutant pass.

## What failed
First run: 4 failures, all test defects: two wrong hand expectations (a `c = lt i, n` temp does interfere with the loop-carried `one`; `sum(0)` loops once, so it takes 12 steps, not 7) and two minimum-mix thresholds guessed too high (irreducible graphs 20 of 500, tight renamings 30). The first mutation run left 3 survivors: `param-livein` (no fixture with a non-parameter live into the entry), `simplify-threshold` (`degree < k` vs `<= k` is invisible unless the smallest-degree and largest-degree nodes differ) and `rename-spill-check` (masked by the later "no register for v" check, both throw IllegalArgumentException).

## Root cause
Expectations were derived from intuition about the program instead of by walking the fixture instruction by instruction, and thresholds on random-mix counts were chosen before measuring. The survivors were a boundary (`<` vs `<=`) that only a dedicated fixture or an exact second implementation can see, a redundancy masked by a later guard, and a rule whose only trigger (a variable read before definition) the generators never produced.

## Rule learned
For a selection algorithm with documented tie-breaks, write a second list-based implementation inside the tests and compare full results exactly on random inputs (plus one hand-checked literal where the two natural choices differ); assert exception messages when two guards throw the same type; and run the generator first, then set mix thresholds below the measured counts.
