# 20261125T1757Z — BitTorrent-style core (bencode, metainfo, picker, swarm)

## Task
`ae.torrent`: strict bencode codec, single-file metainfo (SHA-1 piece hashes, info hash), rarest-first `PiecePicker`, deterministic `Swarm` simulation with seeds that depart, partial peers and poisoners. Overlap check: I read the 35 benchmark directory names (j01-roman .. j35-minisql); none is a bencode, torrent or piece-selection task (j14-json is JSON, a different grammar without canonical-form rules). Existing skills merkle-sync, rsync-delta and kademlia-dht solve different problems.

## What worked
Writing the design in TASK.md and then tests first, with every swarm expectation derived by hand from the tick semantics before running: rarest-first order `[1,0,2]`, a poisoner costing exactly 2 failures and 12 ticks, an early seed departure leaving both leechers with exactly pieces 0..7. Rejection tests were a table of (bad, control) pairs differing by one defect. A per-tick oracle recomputed picker availability from live/unbanned/have state. All 42 tests passed on the first `mvn -q -B clean test`.

## What failed
Nothing failed in the test run (attempts: 1). A 13-mutant pass killed 11 at once. Survivor 1: the string-length guard `len > b.length - start` weakened to `len > b.length` — still rejected, but through the later trailing-data check, so only the error message differed; fixed with a test asserting the message. Survivor 2: dropping the `data.length != pieceSize` fast path in `verifyPiece` is equivalent, since wrong-length data fails the SHA-1 comparison anyway.

## Root cause
The only real gap was a defence-in-depth check whose failure was masked by a later check, so the behaviour test could not see it. This is the general way "rejected anyway" survivors arise.

## Rule learned
When a guard is backed up by a later check, a test that only expects an exception cannot tell them apart: assert the exception message (or the earlier side effect, such as no allocation) for each guard. Decide a survivor is equivalent only by naming what masks it (here: the SHA-1 comparison).
