# 20261118T1556Z: Raft-lite election and replication on a simulated network (level 19)

## Task
Implement Raft leader election and log replication (`ae.raft`) as a tick-driven state machine plus a seeded `SimCluster` with loss, duplication, delay, partitions and crash/restart, and test safety. Overlap check: `benchmark/java/` has j34-vclock (vector clocks) only; nothing on consensus, so no overlap.

## What worked
Writing unit tests per protocol rule first (vote rules, stale-term denial, conflict-only truncation, commit-by-current-term, stale reply not regressing matchIndex) and a SimCluster with a built-in safety checker (one leader per term, globally committed log agrees at every index). A 60-seed chaos test plus a per-tick log-matching check passed on the first run of the implementation. Three mutations (drop the current-term commit guard, drop the up-to-date vote check, always truncate on duplicate) were each caught by failing tests.

## What failed
Attempt 1: one unit test failed (`singleNodeClusterElectsItself`): I expected the first proposal at index 1, but the leader's no-op occupies index 1, so it is 2.

## Root cause
A wrong hand-written expectation: I forgot my own design decision (leader appends a no-op on election) when writing an index literal. It was a test defect, not a code defect.

## Rule learned
When a design adds hidden entries (no-ops, markers), state the resulting index offset in the test comment/assertion message before writing index literals. For protocol code, put the safety invariants in a checker inside the simulator and run it after every tick of randomised fault-injection runs, then kill-check with mutations of each safety rule.
