## Task
Level 20 capstone: `ae.qmc` Quine–McCluskey boolean minimiser with exact (terms, literals) cover, don't-cares, node budget and SOP text parser, in practice/java/20261125T0857Z. Overlap check: read the 35 `benchmark/java` directory names (j01-roman ... j35-minisql); none concerns boolean minimisation, prime implicants or set cover.

## What worked
27 tests green. An independent oracle (DFS over every off-set-avoiding implicant with long bitmasks, no primes, essentials or dominance) agreed on cost for 600 random functions. A 26-mutant pass killed 18 at first; the 8 survivors were analysed: 3 equivalent for cost (option sort order, symmetric tie index in row dominance, row-dominance size guard), 1 pure pruning optimisation (sibling exclusion), and 4 real test gaps (combine with differing masks, budget boundary `>` vs `>=`, parse message for the first illegal letter, the `terms+need >=` prune) which were closed with targeted tests.

## What failed
(1) A test expectation: canonical term order is by value, so the answer prints `C + B + A`, not `A + B + C`. (2) The first search blew a 5M-node budget on dense random n=10 functions, and my reduction restarted after every single change (O(M^3 C)), so `mvn test` hung for minutes. (3) After the rewrite, a real soundness bug: a child search call restarted with all primes alive, so a row dropped by row dominance in the parent could end up uncovered (minterm 29 missing in a 5-variable case). It passed 600 random oracle cases and was found only by running a mutant against the oracle on 20000 functions.

## Root cause
(2) I assumed random functions at n=10 are tractable; exact cover is NP-hard and dense random tables have big cyclic cores, and I chose per-change restarts instead of batched passes. (3) Row dominance is only valid relative to the candidate set it was computed under; I passed `uncovered` (with dropped rows) to children but not the `dead` set, so the child's candidate set was larger than the one that justified the dropped rows. The default 600-case test was too small and too uniform to hit it.

## Rule learned
For reduction-based exact solvers (set cover, SAT, ILP): any state derived under an assumption (dropped rows, killed columns) must be passed down together with that assumption, so inherit all reduction state or none. Test it with a differential oracle at a size large enough to reach rare states: run a bigger one-off sweep (thousands of cases, several seeds) and turn every mismatch into a literal regression test. Measure which instance sizes are tractable (probe node counts and time per seed) before writing "stay fast" tests, and use a node budget plus per-method `-Dtest` runs with timeouts when `mvn test` hangs.
