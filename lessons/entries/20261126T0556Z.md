# 20261126T0556Z — operational transformation (ae.ot)

## Task
Text OT: canonical TextOp (compose/transform/invert/transformIndex), OtServer, Jupiter-style OtClient and a seeded multi-client simulation. Overlap check: read `benchmark/java/` names j01-roman … j35-minisql; none is OT (j18-diff is line diff, j34-vclock is vector clocks).

## What worked
- Provenance-based TP1 oracle: documents with unique characters and disjoint insert alphabets let the test assert survivors keep order, inserted strings stay contiguous and totals add up, which is stronger than "both orders give the same string".
- A protocol invariant checked after every delivery: client doc == server doc at client revision with pending ops applied.
- 33-mutant pass killed 29; survivors are equivalent: delete-boundary `<=` in transformIndex (canonical form never puts an insert after a delete), server base-length guard (masked by transform/apply throwing the same exception before mutation), client apply-before-assign temp (same), simulation replay check (server doc and history are updated together).

## What failed
- Attempt 1: `a.compose(a.invert(doc))` asserted `isNoop()`, but it yields delete+reinsert of equal text, equal in effect and not canonical-noop. Test defect, not code.

## Root cause
Canonical form is a syntactic normal form, not a semantic one: equal effect does not imply equal representation, so "is a no-op" must be asserted by applying to the document.

## Rule learned
For algebras with a canonical form, assert round trips via `apply` on a concrete document and reserve structural `equals` for cases the normal form really guarantees; list which equivalences it does not cover before writing expectations.
