## What worked
Writing TASK.md with exact procedures (DRR turn/credit/reset rules, WFQ tag formula, admission order in the simulator) and deriving literal traces by hand before coding; independent oracles of a different shape (offline round loop for DRR, recompute-all-tags scan for WFQ, tick-by-tick bucket for the shaper). All 44 tests passed on the first run; a 39-mutant pass then showed which tests were weak.

## What failed
- Survivor: the DRR "idle flow keeps no credit" test used a fixture where hoarded credit (190) changed nothing: the second B packet (100) did not fit in the leftover 90. The two deficit resets are redundant with each other, so only a combined mutant exposed it.
- Survivor: the `idle:` check `arrival < start` mutated to `arrival < start - 1`; no fixture had arrival exactly one tick before the start.
- My mutation harness matched `scale / w` inside a comment first (a prefix of `scale / weight`), so that mutant did nothing.
- Shaper `max(arrival, lastRelease)` survives as an equivalent mutant: the token count goes negative (debt), which encodes the same wait.

## Root cause
Fixtures were chosen to look plausible rather than computed to discriminate the guard; redundant guards (two places resetting the same state) hide each other, and the harness anchored a pattern on text that also occurs in comments.

## Rule learned
For every state-reset or credit rule, compute the post-mutation state by hand and pick sizes so that the hoarded value would change the visible order (here: leftover 90 plus a 80-byte packet); mutate redundant guards together, not just one at a time; anchor mutation patterns on full code expressions and check the match is not inside a comment.
