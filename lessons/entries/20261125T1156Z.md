# 20261125T1156Z — ROBDD manager (level 20 capstone)

## Task
`ae.bdd`: reduced ordered BDD manager (unique table, memoised ITE, restrict/exists/forall/compose/andExists, satCount, anySat, cubes, support, size, invariant checker) plus a formula parser with column errors. Overlap check against the 35 `benchmark/java` names: none is a boolean-function library.

## What worked
- Writing the oracle first: random expression trees evaluated directly in Java gave truth tables for eval, satCount, cube coverage, quantifiers, restrict and compose; a separate subfunction-counting oracle verified node counts; n-queens (10, 4, 40, 92) and adder equivalence (canonical ids equal) gave end-to-end checks.
- A 20-mutant pass over `Bdd.java` found one real gap and four equivalent mutants.

## What failed
- First run: `variableOrderChangesSize` expected 18 nodes and got 14. Everything else (including the oracle node-count test) passed.
- Mutant `vars[lo] < v` survived: the order-corruption test only made the hi side or both sides offend, so the lo-side comparison was untested.

## Root cause
- My hand count assumed every subfunction at a y-level gets a node, but a node exists only for subfunctions that depend on that variable (4+2+1, not 7+3+1). The randomized oracle was right; the literal was a miscount (2^(n+1)-2 = 14 confirms).
- The corruption fixtures made two violations at once, so one comparison hid the other.

## Rule learned
When a literal size expectation is derived by hand, cross-check it against the known closed form or the independent oracle before the first run, and count only entities that can exist (nodes depend on their variable). For an invariant checker with a two-sided check (lo and hi child), write one corruption per side in which only that side offends and kill-check each comparison operator (`<` vs `<=`).
