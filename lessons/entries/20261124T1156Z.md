## What failed
- Nothing failed in `mvn test`. The mutation run showed `Equiv` input mapping (`wb[bIndexOfA[i]]`) was untested because the name-matching test used only symmetric gates (AND/OR). My first fix attempt for it was itself wrong (I wrote a "swapped" netlist that is a different function and a wrong counterexample), caught by rereading before running.

## Root cause
Symmetric fixtures hide wiring/permutation bugs: when two operands can be exchanged without changing the result, a test over by-name or by-position mapping cannot distinguish them.

## Rule learned
- For any mapping/permutation code (name-matched ports, column reorders, index remaps) include at least one asymmetric function (`x AND NOT y`, subtraction, MUX) in the fixture and a negative control that differs only by the swapped wiring.
- Event simulators: schedule against the last *projected* value, not the current one, and test a hazard circuit whose trace is a hand-derived literal list (rising input glitches, falling input does not).
- Mutants of redundant code (a re-schedule of an equal value, mask bits that cannot change the lowest set bit) are equivalent: decide by what reads the changed value before adding tests.
