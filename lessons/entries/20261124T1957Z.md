# Lesson 20261124T1957Z

## Task
Elevator-bank dispatch simulation (`ae.elevator`), level 20 capstone. Overlap check done against all 35 `benchmark/java` ids first (PR #136 was rejected for a missed overlap).

## What worked
Writing the per-tick order of events in TASK.md and hand-deriving traces before coding. The invariant checker run after every tick of seeded random and heavy-load runs caught the livelock as a non-terminating run, not a wrong answer. Final `mvn -q -B clean test`: 12 tests, 0 failures.

## What failed
First run: 2 errors and 1 failure, all "not finished". A full car standing on a call's floor was handed the same re-registered call again, reopened its doors every tick and never left. My hand trace C had also assumed the car moved on tick 0, but opening doors consumes the tick.

## Root cause
The dispatcher treated distance 0 as the best cost without asking whether the car could actually serve the call. A reassignment path (unserved call returned to the pool) re-created the same state each tick.

## Rule learned
In dispatch/assignment loops, an agent that already failed to serve an item at its current position must be ineligible for it until the state changes. Add a liveness test (everything finishes within a bound) with full capacity and opposite-direction cases, and re-check hand traces for which actions consume a tick.
