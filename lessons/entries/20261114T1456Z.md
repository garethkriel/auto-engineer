## What worked
27 tests written first, passing on attempt 1 (`Tests run: 27, Failures: 0`). Pushing dialect differences (placeholder numbering, pagination text, whether ORDER BY is mandatory) behind the interface kept the builder free of `if (postgres)` branches. Rejecting bad identifiers with a regex and `split("\\.", -1)` caught `a.`, `.a`, `a..b`.

## What failed
One test I drafted first (`starColumnIsNotQuoted`) was convoluted string surgery that did not state the expectation clearly; I rewrote it before running anything.

## Root cause
Writing the expected value by transforming the actual output makes the test tautological. The real risk in this domain, SQL injection through names or values, is design-level: values only reach `params`, names only pass the identifier pattern.

## Rule learned
For query/command builders: values go only to bind parameters, names pass an allow-list pattern, and every test asserts the full literal SQL string per dialect; never derive an expected value from the actual output.
