# Lesson 20261126T1757Z: exact rational linear algebra

## Task
Level 20 capstone `ae.linalg`: BigInteger `Rational`, immutable `Matrix`, rref/rank/determinant/inverse/nullspace/solve, Bareiss, LU, Faddeev-LeVerrier characteristic polynomial, rational eigenvalues, Gram-Schmidt. Overlap check: `benchmark/java/` names j01-roman..j35-minisql read from `ls`; none is linear algebra.

## What worked
- Exact arithmetic removes tolerances: every property (A*inv(A)=I, P*A=L*U, Cayley-Hamilton p(A)=0, A*n=0) is an `assertEquals`.
- Three independent determinant paths (Gauss, Bareiss, cofactor expansion) plus LU and det(A^T) agreeing on 300 matrices, half rank-deficient by construction.
- A generator-mix test first (>= 30 singular and >= 30 regular of 300) and outcome-mix asserts for `solve` (Unique/Infinite/Inconsistent >= 20 each).
- Triangular matrices as the eigenvalue fixture: eigenvalues are the diagonal by construction, so the oracle is a multiset of diagonal entries.
- Mutation pass: 32/34 killed after adding two tests; every hand literal was derived in a comment before the first run.

## What failed
Three runs. Run 1: compile error, `List.of(v(1, 1))` where `v` returns `Rational[]` spreads the array as varargs. Run 2: one test defect, I wrote `inverse(1/2) == -2`. First mutation pass: 3 survivors.

## Root cause
(1) `List.of(E...)` with a single array argument is ambiguous for generic inference and treats the array as the varargs. (2) A sign slip in a hand-written literal. (3) Survivors: a ragged-row check in `Matrix.of(long[][])` is masked by the same check in `ofRational` (equivalent mutant, the masking guard is named); `ofRational` copying its input had no aliasing test (real gap, fixed); modified vs classical Gram-Schmidt are equal in exact arithmetic because the output vectors are mutually orthogonal (equivalent).

## Rule learned
- Single-array arguments to `List.of`/`Arrays.asList`-style varargs: use `Collections.singletonList(arr)` or `List.<T[]>of(...)` with two or more arrays; never rely on inference.
- Every constructor that accepts a mutable array/grid needs an alias test (mutate the input after construction, assert the object unchanged).
- With exact arithmetic, prefer equality to tolerance and spend effort on independent oracles (second algorithm, defining identity) rather than literals alone.
