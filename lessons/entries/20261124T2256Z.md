# Lesson 20261124T2256Z

## Task
Polynomial toolkit over Z_998244353 (`ae.poly`: `Mod`, `Ntt`, `Poly`, `Shamir`, `Recurrence`), level 20 capstone. Overlap check: listed all 35 `benchmark/java` ids; none concerns polynomials, NTT, secret sharing or recurrences (nearest by theme, j27-primes, is a sieve).

## What worked
Tests first: literal fixtures (x^3+2x+5 ÷ (x+2) = x^2-2x+6 rem -7, Fibonacci generating function 1,1,2,3,5,8,13,21, Shamir shares 1494/1942/2578), naive O(n²) oracles across the schoolbook/NTT cutoff (31/32/33 terms), a divMod invariant (a = q·d + r, deg r < deg d), Fibonacci(10^18) against an independent 2x2 matrix power, and a 2^16-term product plus 50000/20000 division checked at random evaluation points. `mvn -q -B clean test`: 39 tests, 0 failures, passed on attempt 1. A 13-mutant check was run.

## What failed
Nothing failed in the build. The mutation check left the `isConsistent(..., k)` mutant `degree() <= k` alive: no test had k+1 shares of a degree-k polynomial, so the threshold was only tested away from the boundary. Other survivors were equivalent (the naive/NTT cutoff and the `n < order` fast path only change speed).

## Root cause
The Shamir tests covered "consistent" and "tampered" cases but never a point set whose true degree equals k exactly, which is the boundary of the predicate. Boundary tests were missing for a `< k` check.

## Rule learned
For every threshold predicate (`degree < k`, `size <= cap`) write one fixture sitting exactly on the boundary and assert both sides (here: 4 points of a cubic are inconsistent for k=3, consistent for k=4). Justify cutoff-style mutants as equivalent only when both branches are independently verified correct, as the cutoff test across 31/32/33 terms does.
