## Task
Level 17 (larger design): ticket booking with a transactional outbox in four packages (domain, port, adapter, app): `Database.inTransaction` port, `InMemoryDatabase`, `BookingService`, `OutboxRelay` (at-least-once, per-key order, exponential backoff with cap, dead-letter), `IdempotentReceiver`. Overlap check: benchmark has j09-bank, j13-ratelimit, j19-allocate, j24-queue, j32-fsm, j33-pricing, j34-vclock; none shares the outbox/relay core.

## What worked
Writing the design and rules in TASK.md first. Literal expectations for backoff (10s, 20s, cap 25s, dead on third failure), a dedicated test for each guarantee (rollback, per-key blocking, dead head unblocks key, lost ack), and a 40-seed simulation whose oracle is the payload list read from the outbox itself, compared with what the idempotent receiver saw per key. Final `mvn -q -B clean test`: 28 tests, 0 failures; SimulationTest passed 5 extra runs.

## What failed
Attempt 1 failed to compile: two `assertEquals(int, db.inTransaction(...))` calls were ambiguous (int vs Long/Integer overloads) and a helper file landed in a wrong `src/src/...` directory because I used a relative path from an unexpected cwd after `cd`. I also wrote the main code before the tests in this round, which breaks the test-first rule; the tests were then written against TASK.md rules rather than the code, but the order was wrong.

## Root cause
Generic `T` results from a transaction callback make `assertEquals(int, T)` ambiguous; shell `cd` inside a multi-command call moved cwd, so a relative `mkdir`/`cat >` wrote to the wrong place. Writing the whole implementation in one big shell step made it easy to skip test-first.

## Rule learned
For outbox/relay designs: write the business change and the message in one transaction, call the sink outside any transaction, order per key by stopping a key at its first failure (dead messages stop blocking), and test every guarantee with a literal case plus a seeded oracle run. Cast generic transaction results (`(int)`) before `assertEquals`, use absolute paths for file creation, and write test files before main files.
