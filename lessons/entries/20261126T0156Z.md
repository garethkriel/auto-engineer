# 20261126T0156Z — JVM class-file toolkit

## Task
`ae.classfile`: strict class-file reader/writer, modified UTF-8 codec, descriptor parser, full-opcode disassembler with javap-style rendering, and a slot-based stack-depth/locals analyzer. Overlap check: `benchmark/java/` j01..j35 (roman through minisql, incl. j21-sheet, j28-script, j29-kvlog) contain no bytecode/class-file task; the design deliberately avoids sheet/script/regex territory.

## What worked
- Using the running JDK as four independent oracles: `javap -c -p` (67,675 instructions, 28 classes), reflection (members/flags), `writeUTF`/`readUTF` (string codec) and a byte-identical round trip plus analyzer-vs-declared `max_stack` over 2,205 classes (22,137 methods, all exact).
- A synthetic class with one instance of every opcode and every wide form, fed to javap, verified the entries real classes never use (jsr, goto_w, ret, wide ret, dup2_x2, ...). The corpus alone left 18 mnemonics unverified.
- Flip-every-byte property: each mutated image either fails with `ClassFormatException` or re-serialises byte-identically (raw float bits kept for that reason).
- A 24-mutant pass (scratch script, one rule per mutant) found 4 survivors, all closed with a targeted test.

## What failed
- First run had 6 failures: (1) `ldc2_w` effect was registered in the fixed-effect table so the pool check was never reached; (2) handler entry depth 1 never raised `maxStack`; (3) my javap line regex used `.` so a string constant containing U+0085 broke a line (DOTALL needed); (4) interface superclass expectation (reflection returns null, class file says Object); (5) a field fixture with a method descriptor; (6) a hand-counted instruction total off by one.
- Two guessed thresholds failed on first measurement (">100,000 instructions" was 67,675; `dup2_x1` assumed present in the javap set).
- Mutation survivors: `dload`/`lstore_n` local sizes, `invokeinterface` method-handle kind 9 accepting any ref, and `ldc2_w` of a Dynamic constant with a 1-slot descriptor.

## Root cause
Table-driven code with a "fixed" shortcut silently shadows the special-case path (any opcode with an entry in the fixed table never reaches its constant-pool check); tests only asserted the happy value. Handler depth was set in `merge` but only post-step depths fed `maxStack`. Coverage and threshold numbers were typed from intuition instead of measured. Survivors were rules exercised only by the oracle corpus, which asserts `<=` not equality for locals and never uses those forms.

## Rule learned
When a table has both fixed and context-dependent entries, assert the context-dependent ones with a negative case (wrong constant kind) so a fixed entry that shadows them fails. Measure oracle coverage (print opcodes/mnemonics never seen) before choosing "must exercise" lists and thresholds, then close the gap with a synthetic input containing every case. Track maximum depth at every point a value is assigned, not only after instruction steps. Give every size/width rule (long/double = 2) one test per opcode family, because corpus checks that use `<=` cannot see a wrong size.
