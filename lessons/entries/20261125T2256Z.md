# 20261125T2256Z — strict PNG codec

## Task
`ae.png`: Png record, five scanline filters, adaptive encoder, strict decoder (chunk order, CRCs, PLTE rules, zlib size checks, no interlace), verified against `javax.imageio`. Overlap check: `benchmark/java/` j01..j35 contain no image/codec task.

## What worked
- Hand-computed filter literals (derived with the formulas written in comments) plus a random filter/unfilter inverse test.
- Assembling crafted images with valid CRCs from `(type, data)` pairs, each with a control differing only by the defect.
- Using ImageIO as an oracle in both directions caught my wrong assumptions about it rather than about the code.
- A mutation pass of 18 single-rule edits found 3 survivors; each was closed with a targeted test.

## What failed
- Two first-run failures were both test defects: a mistyped Paeth expectation (`paeth(2,4,3)` is c=3, not 4) and the assumption that ImageIO writes `TYPE_BYTE_BINARY` as palette type 3 (it writes gray type 0, depth 1).
- Survivors: signed vs unsigned residual scoring, `ft > 4` vs `ft > 5` and the interlace branch. The last two were masked by a later check that throws a different message.

## Root cause
Expectations were typed from memory of rules or of a library's behaviour instead of derived (Paeth tie table) or probed (what ImageIO emits). Survivors came from asserting only "an exception was thrown" where a later guard also throws.

## Rule learned
When a codec test needs a library's output format, assert on the decoded values through a helper that accepts every legal representation (gray 1-bit or palette), and for every guard assert its own message so a masking later check cannot hide a mutant. Score/heuristic choices (signed-byte residual sums) need a fixture where the two interpretations pick different winners.
