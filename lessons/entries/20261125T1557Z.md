# 20261125T1557Z — reverse-mode autodiff and a tiny MLP

## Task
`ae.ad`: immutable `Mat`, graph `Node` with add (row broadcast), sub, mul, matmul, scale, tanh, relu, sigmoid, square, sum, mean, iterative `backward()`, a finite-difference `GradCheck`, and a seeded `Mlp` trained on XOR. Overlap check: none of the 35 benchmark directory names (j01-roman .. j35-minisql) is autodiff or numeric.

## What worked
Tests first with literal hand-derived gradients (matmul dA = row sums of B, dB = column sums of A; bias grad = sum over rows) plus a finite-difference oracle. All 30 tests passed on the first compile and run. Iterative topological sort handled a 200000-node chain. A 13-mutant pass (flipped sign, dropped broadcast sum, tanh derivative, relu at 0, `=` vs `+=`, skipped reset, sigmoid branch, square factor 2, mean divisor, swapped matmul operand, always-tanh, sgd sign) found one survivor.

## What failed
The sigmoid-stability mutant (`v >= 0` branch changed) survived: for input 800 it produced `Infinity/Infinity = NaN`, and my `Mat.approx` used `abs(a-b) > eps` as the failure test, which is false for NaN, so the stability test passed vacuously.

## Root cause
A tolerance comparison written as "fail if difference is greater than eps" accepts NaN, because every comparison with NaN is false. The helper that all numeric assertions funnel through was therefore unable to fail on NaN output.

## Rule learned
Write tolerance checks as `!(abs(a-b) <= eps)` so NaN fails, and mutation-check numeric helpers with an overflow input (`exp(800)`). A second subtlety: define whether intermediate nodes keep gradient across repeated `backward()` calls (here: reset per pass, leaves accumulate) before writing the double-backward test, otherwise the expected value is ambiguous (12 vs 18).
