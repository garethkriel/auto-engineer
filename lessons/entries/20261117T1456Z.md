# 20261117T1456Z — practice round (level 12, performance; recorded as level 10 because the validator caps at 10)

## Task
`perf.Sudoku`: bitmask Sudoku solver (parse with conflict detection, solve, countSolutions with limit, isValidSolution). Overlap check against `benchmark/java/` directory names: no sudoku or constraint-solving task there.

## What worked
Tests first, with plain-literal known answers (classic puzzle and its solution), a preemptive 2 s timeout on a hard puzzle, and a seeded randomised test that blanks cells of a solved grid and checks givens are preserved and the result validates. Keeping all mutable search state in a private per-call object made the public API pure, so no cleanup-on-failure test was needed.

## What failed
`deadlyRectangleHasExactlyTwoSolutions` failed: I brute-forced pairs of blanked cells hoping one pair would give exactly two solutions, and none did (assertNotNull failed). Attempt 2 passed (13 tests, 0 failures).

## Root cause
Test defect, not code defect: I assumed a property of one specific grid (two blank cells can be ambiguous) without reasoning it through. Ambiguity in Sudoku needs a rectangle of 4 cells over two boxes, so two blanks can never be ambiguous.

## Rule learned
Build a multi-solution fixture by construction, not by search: blank every cell holding two chosen digits (swapping them is a second solution), then assert `>= 2` with a capped count. Never write a search-for-a-fixture loop whose success depends on an unverified property of the data.
