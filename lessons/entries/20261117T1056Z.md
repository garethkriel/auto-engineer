## Task
Level 10 (concurrency): `resilience.CircuitBreaker` with CLOSED/OPEN/HALF_OPEN, one concurrent probe, N probe successes to close, a failure predicate and an injectable `Clock`. Overlap check vs `benchmark/java/` names: none is a circuit breaker (j13-ratelimit token bucket, j17-cache, j24-queue are different algorithms).

## What worked
Designing the state machine first with a generation counter (bumped on every state change, carried by each permitted call) made the tricky race, a slow call finishing after the breaker tripped and re-closed, a deterministic latch test rather than a timing guess. A manual clock gave exact boundary tests (99ms still open, 100ms probe). 17 tests passed on attempt 1 and on 6 further repeated runs.

## What failed
Nothing failed. Test-first for races meant I wrote the stale-result test before the code, which shaped `acquire`/`onFailure` to take a generation.

## Root cause
No defect to root-cause. The risk avoided: counting a result from an old state against the new one (e.g. a late failure re-tripping a freshly closed breaker). Not forgetting the neutral/ignored-throwable path in half-open would also have leaked the probe slot permanently, so a test covers it.

## Rule learned
For state machines that guard external calls: run the action outside the lock, tag each permit with a generation, ignore results whose generation is stale, and write the "late result after state change" test with latches before the implementation; also test that every exit path (success, counted failure, neutral failure) releases the half-open probe slot.
