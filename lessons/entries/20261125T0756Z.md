## Task
Level 20 capstone: `ae.shellx` bash-subset word expansion (quote lexing, brace lists and sequences, `${}` operators, word splitting) in practice/java/20261125T0756Z. Overlap check: read the 35 `benchmark/java` directory names (j01-roman ... j35-minisql); none is a shell lexer or brace/parameter expansion pipeline.

## What worked
12 tests green: 9 literal tests plus 3 differential tests against real `bash` run with `set -f` (600 random valid lines, 300 malformed lines with exact error position, literal list). Using the real tool as oracle found four semantic gaps my literal tests had not imagined. A 15-mutant pass left one survivor, which was an equivalent mutant (raw PLAIN text never occurs inside double quotes), removed by simplifying the code; 5 other survivors were real test gaps and were closed with literal tests (`{a},b}`, negative step, padding by the second endpoint, `"\\"`, `${#U}`, `${#B:-z}`).

## What failed
Five `mvn` runs before green: (1) test source typo (`x("{"",x}")` unescaped quotes); (2) `$B{1..3}` gave `b1..b3` instead of bash's empty result; (3) `$1` is a positional parameter in bash (empty), I treated `$` as literal; (4) `"$A"{01..03}` lost the value because the name scan ran across the closing quote into the sequence digits; (5, found only after raising the run to 1500 lines) `{1..},}{`: bash skips a `}` that comes before any comma, I closed the group at the first `}`.

## Root cause
I specified the semantics from memory of bash instead of from its behaviour, and the first generator produced only well-formed lines, so the error path was never exercised (errors=0 in the first measured mix). Specific causes: brace output was tagged as literal text although bash treats it textually; a closing quote left no marker, so `$NAME` scanning could run on; the brace matcher assumed plain nesting.

## Rule learned
When re-implementing a subset of an existing tool that is installed (bash, grep, sed...), use it as a differential oracle from the first test, and measure the generator's outcome mix (valid vs rejected) before trusting it: if one outcome is zero, write a second generator for it. Probe edge syntax directly in the real tool (`bash -c 'printf [%s] ...'`) before writing the matcher. For multi-stage pipelines, make the intermediate representation carry per-character provenance (quoted, expanded, literal) and add zero-width end markers where a token must stop.
