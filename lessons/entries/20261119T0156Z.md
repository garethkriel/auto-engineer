# Lesson 20261119T0156Z

## Task
Level 20 capstone: `ae.stream.WindowEngine`, an event-time windowed aggregation engine (tumbling/sliding/session windows, bounded-out-of-orderness watermark, allowed lateness, dropped-event side output, CRC-checked checkpoints). Overlap with `benchmark/java/` names checked: none is stream/window processing.

## What worked
Writing the firing, lateness and merge rules as exact inequalities in TASK.md first (`end <= wm` fires, `end + lateness <= wm` purged) let the literal boundary tests be written before any code. A brute-force oracle with a naive O(n²) prefix watermark, a checkpoint-at-random-points equivalence test and two mutants (`<=` to `<` in the drop rule and the session touch rule) that failed 2 and 5 tests confirmed the tests can fail. Computing all throwing values before mutating made the "failed process leaves snapshot bytes unchanged" tests pass first time.

## What failed
First run: 30 of 31 tests passed; the differential test failed on the `dropped()` list because one event's windows were listed newest-first by the engine and oldest-first by the oracle.

## Root cause
The sliding-window assignment loop walks start values downwards, and I never specified the order of multiple windows per event. An unspecified ordering in an output list compared with `assertEquals` made engine and oracle disagree although the contents were identical.

## Rule learned
When an API returns a list derived from a set (windows per event, matches, children), state the order in the design and make the implementation produce it by construction (here: ascending window start); then the oracle can compare lists directly instead of sets.
