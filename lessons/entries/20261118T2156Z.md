## What failed
No test failed. Weak points: the first drafts of two tests (skewed-clock log, criss-cross) contained filter/ternary/`|| true` placeholders because I was still deciding the scenario; I rewrote them with explicit expected lists before the first run. One mutation (`covered.add(p)` instead of all ancestors of p) survived; it is an equivalent mutant because every ancestor of a common ancestor is itself common.

## Root cause
Placeholder assertions appear when a scenario's expected result has not been worked out on paper; deciding timestamps and parents first makes the expected list a plain literal. A surviving mutant must be classified (equivalent vs missing test) rather than ignored.

## Rule learned
For DAG/ordering tests, give each commit an explicit time and write the expected order as a literal list of named ids before coding the assertion (include a child older than its parent to catch time-only sorting); after mutation checks, state for each survivor whether it is equivalent or needs a new test.
