## Task
Level 20 capstone: Kademlia DHT simulated in-process (`ae.kad`, practice/java/20261125T1357Z): XOR NodeId, LRU k-bucket routing table with replacement cache, iterative lookup (alpha, k), put/get, failure handling. Overlap check: compared all 35 `benchmark/java` directory names (roman ... minisql); none is a DHT/routing task.

## What worked
Tests first (29: 4 NodeId, 11 routing table, 14 DHT) with a brute-force oracle over alive nodes as the source of truth for lookups. Handlers that never issue RPCs (stale contacts recorded as suspects and pinged at the end of the client operation) avoided nested ping chains. A 12-mutant pass killed 11; the survivor only affects RPC cost.

## What failed
Three runs were needed (attempts=3). Run 1: lookups returned far-away nodes, because `join` only looked up the node's own id, leaving distant buckets empty. Run 2: with 25% dead nodes and with every 5th RPC dropped, lookups returned 7 or 6 results instead of 8. Also, a mutant run without `clean` left stale classes after the file was restored, giving one spurious failure.

## Root cause
(1) The Kademlia join procedure includes refreshing buckets farther than the nearest neighbour; I implemented only half. (2) A single failed RPC was treated as death, evicting a live contact and shrinking the shortlist; and after mass failure the tables hold dead entries that only a repair pass removes, so expecting exact results immediately was a wrong test expectation. (3) `mv` of a `.bak` keeps the old mtime so incremental compilation did not rebuild.

## Rule learned
For routing/overlay protocols write the full join/refresh/repair procedure into TASK.md before coding and test connectivity first on a small exact-oracle network; treat one failed RPC as "retry once" before evicting; test post-failure exactness only after an explicit repair phase. A test that kills the one rule matters most when a different path masks it (a lookup that queries the dead contact hides a missing suspect-eviction): build a fixture where only that path can act. Always `mvn clean test` in mutation harnesses and the final check.
