# Lesson 20261120T0757Z — exact computational geometry engine (level 20)

## Task
`ae.geom`: exact integer predicates, segment relations, convex hull, polygon point location, calipers diameter,
closest pair, Shamos-Hoey any-intersection sweep.
Overlap check: `benchmark/java/` names (j01-roman ... j35-minisql) contain no geometry; `spatial-quadtree` is a point index only.

## What worked
- Capping coordinates at 1e9 made every cross product fit in `long` (diff <= 2e9, product <= 4e18, difference <= 8e18); only the sweep comparator needed BigInteger.
- Independent oracles (all-triples extreme points, O(n^2) segment test, brute-force distances) on tiny coordinate ranges forced collinear/touching/vertical degeneracies; outcome mix was asserted (found and none both > 100).
- Mutation checks killed: insert/remove event order, disabled closest-pair strip, strict instead of non-strict touching, removed winding check, inconsistent half-open ray rule. One apparent survivor (`>=` instead of `>` in the ray rule) was an equivalent mirrored convention; the inconsistent variant was killed.

## What failed
First run: 1 failure, `nearMissWithHugeCoordinatesNeedsExactArithmetic`. The "miss" fixture (ends at (m,m-1) and (m,m-2)) actually crosses because the first segment starts below and ends above the second.

## Root cause
I picked end-point offsets by feel without sketching start and end y of both segments; a near miss needs the same side at BOTH ends. Production code was right.

## Rule learned
For near-miss / just-touching fixtures write start and end coordinates of both segments in a comment table (who is above at each x) before running; to build a miss, keep one segment strictly on one side at every shared x. When a mutant survives, first ask whether it is an equivalent mirrored convention before adding a test.
