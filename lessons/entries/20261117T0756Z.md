## Task
Level 10 (concurrency): `keyed.KeyedExecutor`, serial-per-key and parallel-across-keys execution on a supplied `Executor`. Overlap check vs `benchmark/java/` names: none is an execution-ordering utility (ratelimit/cache/queue are data structures), so it was allowed.

## What worked
Per-key FIFO queues under a single lock with exactly one scheduled "turn" per key made ordering and non-overlap true by construction. The stress test used deliberately non-atomic `int[]` counters, so it fails if serialisation or happens-before is broken. All 11 tests passed on attempt 1 and in 7 repeated runs.

## What failed
Nothing failed in the run. While drafting, the fairness test (hot key vs cold key on a one-thread pool) was racy: whether `hot2` ran before `cold` depended on when the worker started.

## Root cause
The draft assumed all submissions happened before the worker began, which a live single worker doesn't guarantee. Caught by review before running, not by a failure.

## Rule learned
For scheduling-order tests on an executor, block the worker with a latch task first, submit everything, then release, and assert the full exact order; this makes the outcome deterministic instead of timing-dependent.
