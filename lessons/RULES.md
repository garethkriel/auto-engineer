# Rules learned

General rules distilled from recurring lessons in `lessons/entries/`. Only maintenance rounds change this file. Each rule is one line and names the lesson entries it came from.

- Boundary checks on computed doubles need a small epsilon (e.g. 1e-9), and the boundary value itself must be tested. (20261112T1615Z)
- Every test must be able to fail: assert on real behaviour of the code under test, never `assertTrue(true)` or an empty body. A test that passes against a stub is a defect. (rejected PR #2)
- Lesson entries need a concrete root cause and a rule that would prevent a specific mistake; "None" or "use the standard library" is rejected. (rejected PR #2)
- Run logs and PR bodies must quote real test output (test counts, last lines of `mvn` output), not just "exit 0". (rejected PR #2)
- Maven "Could not find artifact" while curl to the same URL returns 200 is a transient negative-cache failure: loop `mvn -q -B -U test` (up to ~6 tries), confirm with a final run, and don't count it as a debug attempt. (20261113T0857Z, 20261113T1002Z, 20261113T1156Z, 20261113T1544Z)
- Template poms with the exact `CHANGE_ME` placeholder and `diff` against `templates/java/pom.xml`; only the project artifactId line may differ. (20261113T1757Z)
- Use `Math.floorMod` for wrap-around indexes and a boolean/Optional instead of an in-band sentinel; always test with `Integer.MIN_VALUE`/`MAX_VALUE` inputs. (20261113T0757Z)
- Make failures side-effect free: validate arguments and compute every throwing result (e.g. `Math.addExact`) into locals before mutating fields or static counters. (20261113T1156Z)
- For value classes, normalise in the single factory so `equals`/`hashCode` compare plain fields; use `Math.*Exact` or `BigInteger` for overflow-prone arithmetic. (20261113T1002Z, 20261113T1544Z)
- Re-read hand-written expected values for ambiguity before running tests; a wrong expectation is a test defect, not a code defect. (20261113T0857Z)
- Before choosing a practice topic, list `benchmark/java/` directory names and reject any task whose core algorithm matches one (word-frequency/top-k counting, interval merging, LRU cache, CSV parsing, LCS, expression evaluation, graph search, bank accounts, counters, streams, file indexing, Roman numerals, minimal line diff/edit scripts (j18-diff) even when wrapped in unified-diff or merge features, in-memory SQL engines with execute/Result/NULL ordering). A different surface (new names, extra methods) does not count as a different task; state the overlap check in the lesson and run log. (rejected PRs #13, #16, #18, #92, #136). Read the directory names above rather than claiming from memory that no task matches; skills must not contain a benchmark solution
- For formatted-output or hand-counted expectations, derive widths/counts from the fixture first and assert full contents (e.g. list the terms) rather than a bare size; when a table-driven date expectation fails, enumerate the days against the calendar before touching code. (20261113T2056Z, 20261113T2256Z, 20261114T0256Z)
- Inject time/sleep behind a tiny interface for testability; in any loop catching `Exception`, handle `InterruptedException` first and restore the interrupt flag. (20261114T0156Z)
- Generic APIs taking `Class<T>` tokens: test with `int.class` first and box the token before `cast`/`isAssignableFrom`. (20261114T0500Z, 20261114T0556Z)
- Callback registries: iterate over a snapshot and test a handler that mutates the registry during dispatch. (20261114T0556Z)
- Run `mvn -q -B test` once before applying the Maven retry loop; report counts with `mvn -B test | grep "Tests run:"`. (20261114T0356Z)
- Skills `inverted-index` (topTerms) and `int-range` (merge) overlap benchmark territory; do not extend them in practice rounds. (20261114T0056Z)
- File persistence: test round trip, overwrite, and that no temp files remain; write via temp file + atomic move in the same directory; build path keys from `Path` name elements joined with `/`; when shifting numbered files, go from the highest index down. (20261114T0857Z, 20261114T0956Z)
- Memoising wrappers: a separate volatile "done" flag written after the value (never null as sentinel), set only after the supplier succeeds; test null results, failure-then-success and concurrent first access. (20261114T1156Z)
- Custom Collectors: accumulate an immutable type with an identity element; test `combine(EMPTY)` both ways and a parallel-stream run against the sequential result. (20261114T1058Z)
- Wrapper/middleware chains: write one ordering test first, derive every other test's `use(...)` order from it and annotate layer order in a comment. (20261117T0156Z)
- Enumeration tasks: get ordering and de-duplication by construction (sort inputs, skip equal siblings, ascending loops); test with published counts plus a validity-and-order invariant. (20261117T0257Z)
- DP routines: pair plain-literal known answers with randomized brute-force cross-checks and validity checks on the reconstructed solution; never write expectations as expressions mirroring the code. (20261117T0356Z)
- When a differential test uses another engine (e.g. regex) as oracle, translate token by token with each unit grouped, and suspect the oracle first when it disagrees. (20261117T0456Z)
- Concurrency tests: run the class 5-8 times before counting it as passing; gate an intended "loser" behind a latch plus a delay, never a latch alone the winner releases before acting. (20261117T0556Z)
- Scheduling-order tests on an executor: block the worker with a latch task, submit everything, release, then assert the exact order. Any barrier/latch N tasks must reach together needs a pool of at least N threads, sized from the same variable. (20261117T0756Z, 20261117T0856Z)
- State machines and pools guarding user callbacks: run callbacks outside the lock, tag permits with a generation and ignore stale results, reserve the slot before calling user code and release it on every exit path (success, counted failure, neutral failure, null, close mid-flight), and assert `size()`/state after each path. (20261117T1056Z, 20261117T1156Z)
- Practice rounds only ADD files: never edit `skills/java/INDEX.md` (maintenance adds rows) and check `git diff --name-status <merge-base>` shows only `A` lines before pushing; edit generated code with the Edit tool, never a `sed` range delete. (20261117T0956Z)
- Parsers that report "which terminator ended me" must return it in a result value or reset the field on every exit path (including end of input); test an inner block closing with the outer one unclosed. (20261117T1756Z)
- Build multi-solution or special-case fixtures by construction (e.g. blank every cell holding two digits), never by searching data for a property you have not proved; when a test mutates a fixture several times, annotate the running count. (20261117T1456Z, 20261117T1356Z)
- Take 64-bit arithmetic expectations from `BigInteger` or published literals; scan new tests for ternaries and `.size()`-only assertions before the first run. (20261117T1556Z)
- `result.json` `passed` must come from the final `mvn -q -B test` in the session, and the CI `tests` check must also be green: rejected PR #58 claimed passed while CI failed. Run the whole round folder from a clean `target/` (`mvn -q -B clean test`) and run `python3 eval/validate_round.py` before pushing; the validator caps recorded level at 10. (rejected PR #58, 20261117T1356Z)
- Position/column assertions: compute the expected column from `doc.indexOf(token) + 1` (or mark it with a counted comment) and include the document in the failure message; when an input could be claimed by several grammar levels, name the rule that fires first and prefix with a letter to force the level under test. (20261117T1956Z, 20261117T2056Z)
- Binary file formats: define layout sizes as named constants (HEADER/FOOTER_SIZE) used by tests, add `throws` to tests calling checked-corruption APIs, run exhaustive truncation and flip-every-byte loops asserting "exception or identical data", test structure validation with crafted images re-sealed with a valid checksum, build the whole image in memory so failures leave no file, and compare keys in the file's byte order (unsigned UTF-8). (20261117T2156Z, 20261117T2256Z, 20261117T2356Z)
- Before the first run, reread drafts for placeholder expressions and ternaries (a lambda over an indexed loop variable invites them); use a plain `if (opt.isPresent())` instead. (20261117T2256Z, 20261117T2356Z)
- Network/socket code: bind to port 0 on loopback, inject loss/delay/time through predicates or tiny interfaces, and assert exact counts; for half-close, idle timers and connection caps write one dedicated test each so the failure is observable. (20261118T0156Z, 20261118T0256Z, 20261118T0356Z)
- Augmented or indexed data structures (skip list spans, indexed heaps): keep a package-private invariant checker, make ties deterministic, and run it after every mutation of a randomized differential test against a JDK model (TreeMap/TreeSet). (20261118T0456Z, 20261118T0556Z)
- Maintenance: loop over `skills/java/*/` against INDEX.md rows every round and index missing skills only after their tests pass in the session (six were missing again after the 0656 round because practice rounds may not edit INDEX). (20261118T0656Z, 20261118T1256Z)
- Undo/rollback structures and offline timelines: after every rollback assert all observable state, test that no-op operations are not recorded, and cross-check against a naive rebuild oracle fed by a generator that tracks its own live set. (20261118T0756Z)
- Event-sourced designs: keep `decide` pure and `apply` a fold, append with the version that was read, test stale-version races with a decorating store that sneaks in a write, and verify projections against an oracle recomputed from aggregates. (20261118T0856Z)
- Outbox/saga/write-ahead-log designs: write the change and the message in one transaction, call external sinks outside it, derive state only from the log, make steps idempotent, and test recovery with a decorator that crashes at every append index checked against a net-effect ledger. (20261118T0956Z, 20261118T1056Z)
- Refactoring a multi-guard function: copy guard order verbatim and add a differential grid over the cross-product of invalid values (null/empty/unknown per parameter) against the legacy oracle. (20261118T1156Z)
- Protocol/distributed simulations: put safety invariants in a checker inside the simulator, run it after every tick of seeded fault-injection runs, and kill-check it with a mutation of each safety rule; when a design adds hidden entries (no-op markers), state the index offset before writing index literals. (20261118T1556Z)
- Placement/replication algorithms: pair exact table-hasher tests with property tests for minimal movement, compare summed fractions with a 1e-12 tolerance, and say what happens to an entity a tie-break eliminates. (20261118T1656Z)
- Replicated types (CRDTs): merge is a join (idempotent, commutative, associative), equality is structural, every tie breaks by a total order, and convergence is tested by gossip against an oracle of observed operations. (20261118T1756Z)
- Search/resolver code: record tentative-choice failures as messages (deepest wins) and throw only when exhausted; compare all pairs of a published ordering chain; verify completeness against a brute-force oracle on tiny seeded instances. (20261118T2257Z)
- Hierarchical stateful structures (filesystems, parent-pointer trees): keep an `fsck`-style invariant checker plus a naive path-keyed model, compare after every random step, and test snapshot/copy by mutating copy and original independently and restoring a snapshot twice. (20261118T2356Z)
- Handle-lifetime resources (transactions, snapshots, open files): do verification reads inside try-with-resources, assert the active count before the verifying read, and fix edge semantics in TASK.md before writing tests. (20261118T2056Z)
- DAG/ordering tests: give each node an explicit time, write the expected order as a literal id list, and include a child older than its parent. Recovery sweeps: write the per-job event sequence first and give multi-crash tests a retry budget of failures + crashes + 1. (20261118T2156Z, 20261118T1956Z)
- INDEX.md edits: after editing, check `grep -n "^|---" skills/java/INDEX.md` shows one separator and the row count equals the number of skill folders (rejected PR #96); the index drifts every 6h by design, so diff `ls skills/java` against it first each maintenance round. (20261119T1256Z)
- Rejection tests: assert on the exception message or add a control input differing only by the one defect that must load, so rejection for an unrelated reason (e.g. leftover draft code corrupting a header) fails the test; write tests before the implementation. (20261119T1756Z)
- Test generators: state the validity invariant over the whole relation (e.g. dependency graph, grammar levels) and parenthesise non-atomic productions; add a "generated input is valid" check first and measure the outcome mix of randomized runs before asserting minimum counts. (20261119T0956Z, 20261119T1456Z, 20261119T1656Z)
- Simulations: choose timeouts and partition lengths from the dissemination model before writing tests, and test an invariant checker by corrupting state and calling it directly, not via a step that can self-heal. (20261119T1556Z)
- Hand-computed layouts (allocators, GC, versioned stores): write a comment table of the state next to the fixture and derive counts from it; kill-check each rule of a graph/ordering algorithm by mutating that single rule. (20261119T1356Z, 20261119T0456Z, 20261119T0856Z)
- A failing static initialiser shows up as `NoClassDefFoundError` in every test: run one test and read the first stack trace first. (20261119T0556Z)
- Performance/complexity tests must call every routine whose complexity matters (build AND lcp, not just build); mutation harnesses need a per-mutant timeout (a termination-breaking mutant hangs `mvn test`), restore the file in a `finally`/trap, and report patterns that matched nothing. (20261120T0856Z, 20261120T0456Z, 20261120T1156Z)
- Geometry/segment/layout fixtures: sketch both end coordinates (a near miss needs the same side at BOTH ends) and check legality of hand-built positions before using them; derive each expectation from the fixture, not from design intuition. (20261120T0757Z, 20261120T1056Z, 20261120T0556Z, 20261120T0956Z)
- Buffers sized from a formula must use the worst-case parameter (max radix = 6 bits/digit), and the first randomized test must include that parameter; for non-terminating or cyclic inputs give every copy/traversal a node budget and test it, because an OOM kills the whole surefire fork. When `mvn test` dies with `Java heap space` and no report, run each method with `-Dtest=Class#method` to find the culprit. (20261124T0356Z, 20261124T0456Z)
- "Covered by earlier rules" analyses and survivor mutants: enumerate what each earlier rule covers before writing the expected list; for a surviving mutant, decide equivalent vs test gap by reasoning about what reads the changed value, and a mutant helper must assert its pattern matched and that the build compiled. (20261124T0156Z, 20261124T0356Z, 20261124T0556Z)
- Protocol/session oracles are written in terms of what the system has sent and the client has acked, never what the client saw; generators over a grammar must be checked for valid output (no empty words) before differential use. (20261124T0556Z)
- Mapping/permutation code (name-matched ports, index remaps, column reorders): fixtures need an asymmetric function (`x AND NOT y`, MUX, subtraction) plus a negative control differing only by swapped wiring; event simulators schedule against the last projected value and test a hazard circuit with a literal hand-derived trace. (20261124T1156Z)
- Invariant checkers get a dedicated test class with one hand-built corrupt structure per rule (assert the message prefix); a surviving "checker rule dropped" mutant is a test gap. Strict decoders: one CRC-resealed crafted image per format redundancy plus a control differing only by that defect, an explicit row cap, and size checks before allocation. (20261124T1356Z, 20261124T1456Z)
- Expected counts and winners are derived, not guessed: write inclusive-bound formulas (`(last-first)/step+1`) and byte-size arithmetic as literal comments, and order tied matches by the documented sort key with `start = end - length` noted. (20261124T1456Z, 20261124T1656Z, 20261124T1756Z)
- Stateful streams and simulators: each `reset()` needs a partial-match-then-reset test; justify equivalent mutants by naming the invariant that makes them unobservable; write the test file before the implementation. (20261124T1656Z, 20261124T1756Z, 20261124T1356Z)
- Dispatch/assignment loops: an agent that already failed to serve an item at its position is ineligible for it until state changes; add a liveness test (everything finishes within a bound) with full capacity and opposite-direction cases. (20261124T1957Z)
- Comparator-relative APIs (floor/ceiling/higher/lower): list keys in comparator order before writing expectations. For threshold predicates (`degree < k`, `size <= cap`) add one fixture exactly on the boundary and assert both sides. (20261124T2056Z, 20261124T2256Z)
- DP states containing an index that does not affect the future (line number under constant width) need a normalisation step and a peak-state-count assertion; leading/trailing discardable items need a fixture where keeping them would make the line infeasible. (20261124T2156Z)
- Game/search code: state the coordinate convention (origin, row order) in TASK.md and the class doc, share it between `parse()` and move numbering; test table depth by deepening one table 1,2,3,4 against the plain oracle, and test pruning windows with a node-count inequality since values cannot reveal them. (20261124T2356Z)
- Classification/equality rules: write the rule table first, generate inputs from the post-classification domain, test both sides of every comparison, and run a mutation pass flipping each comparison once; ones-complement zero has two representations. (20261125T0357Z)
- Structures with lazily-collected garbage: any size assertion must `compact()` first and compare an identical-copies fixture against a different-copies control; each conjunct of a multi-part safety guard gets a fixture violating only that conjunct. (20261125T0456Z)
- Fixed-depth tries and strict verifiers: comment table of level/child-level before the descent loop, first-put-on-empty test, over-long variant of every length check, and never memoise recursively with `computeIfAbsent`. (20261125T0556Z)
- Numeric assertions: write tolerance checks as `!(abs(a-b) <= eps)` so NaN fails, and mutation-check numeric helpers with an overflow input (`exp(800)`); fix whether intermediate nodes keep state across repeated passes before writing the second-pass expectation. (20261125T1557Z)
- A guard backed up by a later check (length vs trailing-data, size fast path vs hash compare) cannot be told apart by "expects an exception": assert the message or earlier side effect, and call a survivor equivalent only by naming what masks it. (20261125T1757Z, 20261125T0957Z)
- Consensus/overlay protocols: write the full procedure (join + refresh, learner catch-up Sync, retry once before evicting) into TASK.md first; give every "ignore stale ballot/term" guard a direct one-message unit test; isolate a node on all links when it must stay behind; `mvn clean test` in mutation harnesses (restored files keep old mtimes). (20261125T1456Z, 20261125T1357Z)
- Wrap-around ranges: clamp the computed span to the ring size and test a "wrapped" box narrower than one cell; derive literals from bit layouts, not memory of published values; exclude boundary rows from invertibility properties by construction. (20261125T1656Z)
- Re-implementing a subset of an installed tool (bash, grep): use it as a differential oracle from the first test, measure the generator's valid/rejected mix, and carry per-character provenance through multi-stage pipelines. (20261125T0756Z)
- Reduction-based exact solvers (set cover, SAT): pass derived state (dropped rows, dead columns) down together with its assumption; probe tractable sizes before "stay fast" tests and keep a node budget. (20261125T0857Z)
- Mutation harnesses (recurring across rounds): TAB-delimited rows, one single-line mutant per row, assert each pattern matched and the build compiled, `trap` to restore the file on EXIT/INT/TERM, and treat a surviving "guard removed" mutant as either a masked redundancy (name the masking guard) or a missing one-byte-over boundary test; give each of two overlapping budget guards a fixture that trips only that guard. (20261126T0856Z, 20261126T0957Z, 20261126T1056Z, 20261126T1157Z)
- Every constructor or factory accepting a mutable array/grid/list needs an alias test (mutate the input afterwards, assert the object unchanged); with exact (rational/BigInteger) arithmetic prefer equality over tolerance and invest in independent oracles (second algorithm, defining identity). Never pass a single array to varargs helpers like `List.of`. (20261126T1757Z)
